# /research — 도메인 조사 → context.md (mk2)

신규(또는 정보 부족) 고객사의 조사를 모아 `projects/<기업명>/context.md`를 만들고,
회차가 바뀌어도 유지될 장기 기억은 `memory/clients/<기업명>.md`에 적재한다.
`$ARGUMENTS` = 기업명.

## 원칙 — 조건부(라우팅)로 최소 작업
> **이미 아는 고객사면 외부 웹 리서치를 생략/축소한다.**
> - `memory/clients/<기업명>.md`가 있고 최근(updated) 정보가 충분 → **사내 확인만**, 외부 웹은 생략(또는 "최근 뉴스"만).
> - 신규·미지 고객사 → 사내 + 외부 웹 풀 리서치.
> 회사 개요를 두 곳에서 중복 생산하지 않는다: **사내 정보가 1차, 외부는 사내에 없는 것만 보강.**

## STEP 1. 사내 정보 (1차 소스)
- `memory/clients/_INDEX.md`에서 폴더↔고객사 매핑 확인 → 관련 `projects/<폴더>/`의 `요구조건.md`·`MEMORY.md`·회의록 확인.
- (연동돼 있으면) Gmail·Slack·Notion에서 최초 문의·미팅로그·상업조건을 원문 근거와 함께 수집.
- 확인된 사실만. 없는 건 `(미확인)`.

## STEP 2. 외부 웹 리서치 (조건부 — 신규·미지일 때만)
- 기업 개요·AI 도입 현황·조직/채용·최근 뉴스·경쟁사 동향. 회사 기본은 사내에 있으면 재조사 금지.
- 불확실은 `[추정]`/`[미확인]`, 출처(공식 홈페이지 필수)를 답는다.
> 토큰 절감: 이 단계는 서브에이전트로 돌려 **요약만** 받는 것을 권장(원문·검색결과를 메인 컨텍스트에 쌓지 않음).

## STEP 3. context.md 작성 (제안 설계 입력)
`projects/<기업명>/context.md`에 아래를 채운다(제안 타입·대상·목표·제약의 근거):
- 교육 대상/직군, 인원, 목표, 형태(온·오프/사내망), 인프라·보안 제약, 사용 도구 수준
- 확정 요구사항·일정·장소(있으면), 미정은 `[협의 필요]`
- 도메인 특이사항(업종·최근 이슈)과 그것이 커리큘럼에 주는 함의

## STEP 4. 장기 기억 갱신 (memory/clients)
- `memory/clients/<기업명>.md`가 없으면 `memory/clients/_TEMPLATE.md`를 복사해 생성, `_INDEX.md`에 매핑 추가.
- 회차가 바뀌어도 유지될 것만(담당자 성향·확정 조건·통한 것/거절 사유·선호 포맷). 이번 회차 경과는 `projects/<폴더>/MEMORY.md`.
- 모든 항목에 `[출처: 파일 또는 날짜]`. 확정 금액·계약은 Notion 「영업/제안현황」이 원본(여기엔 흐름만).

## 산출
- `projects/<기업명>/context.md` (다음 단계 `/propose`의 입력)
- `memory/clients/<기업명>.md` (신규/갱신)

→ 다음: `/propose <기업명>` 으로 content.json 작성·검토·빌드.
