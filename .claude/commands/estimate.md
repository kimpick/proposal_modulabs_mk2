# /estimate — 견적서 · 이메일 초안 (Step 5)

`$ARGUMENTS` = 기업명.

## 전제 — 커리큘럼 확정 이후에만

> 견적은 확정된 커리큘럼(시간·회차·트랙 구성) 위에서만 계산된다.
> `content.json`이 `/review` PASS 전이면 **여기서 멈추고** 커리큘럼을 먼저 확정한다.
> 커리큘럼이 바뀌면 총시간이 바뀌고 견적·이메일을 전부 다시 만들어야 한다.

## 입력

| 소스 | 읽을 값 |
|---|---|
| `projects/{기업명}/요구조건.md` | 담당자·이메일·인원·예산 범위·협의된 단가 |
| `projects/{기업명}/제안서*/content.json` | 트랙·세미나별 시간, 회차, 과정명 |
| `templates/estimate/template.md` | 견적서 md 골격 |
| `templates/estimate/references/*.tsv` | 실제 발행 견적서 양식 (구분 체계·비고 문구) |
| `projects/상명대학교/` | 3종 산출물 완성 사례 (md·csv·html 형식 기준) |

제안서 폴더가 여러 개면 어느 것을 기준으로 할지 사용자에게 확인한다.

## 산출물 — 3종 (`CLAUDE.md` 최종 산출물 규격)

```
projects/{기업명}/
├── {기업명}_AI교육_견적서.md          ← 참고용 (사내 검토·품의)
├── {기업명}_AI교육_견적서.csv         ← 스프레드시트용 (마스터 시트 붙여넣기)
└── {기업명}_AI교육_이메일_초안.html    ← Gmail 붙여넣기용
```

## 산출 규칙

### 단가
- **기본 시간당 600,000원** (주강사 1인 오프라인, 교육 운영 및 기업 이윤 포함).
- 차수·규모 할인을 적용하면 **참고사항에 근거를 반드시 명기**한다.
  예: `시간당 단가 45만원 적용 (기본 단가 60만원에서 차수 할인 반영)`
- `요구조건.md`에 협의된 단가 범위가 있으면 그 범위를 따른다.
- 확정할 근거가 없으면 **추측하지 말고** `[협의 필요]`로 두고 사용자에게 묻는다.

### 계산
- 강의료 = 시간 × 시간당 단가. 트랙·세미나별로 행을 나눈다.
- **소계는 천원단위 절사** 후 VAT 10%를 별도 행으로 표기.
- 총합계 = 소계 + VAT.
- `공급가액`이 `수량 × 단가`와 딱 맞지 않는 항목(협의로 반올림한 경우)은 그대로 두되,
  **소계·VAT·총합계는 표기된 공급가액들과 반드시 일치**해야 한다. md와 csv의 금액도 서로 같아야 한다.

### 구분 체계 (csv `구분` 열)
| 구분 | 들어가는 것 |
|---|---|
| 교육비 | 오프라인 강의료, VOD·온라인 콘텐츠 |
| 운영비 | 교재·실습 자료, 수료증, 장비 대여 |
| 재료비 | AI 인프라 세팅, 툴 계정·구독 |

md 쪽은 `4-1 오프라인 강의료 / 4-2 온라인 콘텐츠 / 4-3 부대비용`으로 묶는다
(운영비·재료비가 md의 부대비용에 해당).

## csv 형식

- **UTF-8 with BOM** 으로 저장한다. BOM이 없으면 Excel에서 한글이 깨진다.
- 헤더: `구분,항목,수량,단위,단가,공급가액,비고`
- `구분`은 그룹 **첫 행에만** 쓰고 이어지는 행은 빈칸으로 둔다 (병합 셀 표현).
- 마지막 3행은 `소계` / `부가세(10%)` / `견적금액` — 금액은 `공급가액` 열에만 넣는다.
- 금액은 숫자만 (쉼표·원 표기 없음). 수량·단위는 `1회`, `4시간`, `30인`, `1식` 처럼 단위를 붙인다.

```csv
구분,항목,수량,단위,단가,공급가액,비고
교육비,세미나 1: 과정명,1회,4시간,450000,1800000,* 주강사 1인 오프라인 참여
,세미나 2: 과정명,1회,3시간,450000,1350000,* 주강사 1인 오프라인 참여
운영비,교재 및 실습 자료 (PDF 교재· 프롬프트 템플릿),4회,1식,75000,300000,
,수료증 발급 (전 과정 이수자),30인,1회,3300,100000,디자인 및 발급 포함
소계,,,,,6700000
부가세(10%),,,,,670000
견적금액,,,,,7370000
```

## 이메일 초안 형식

Gmail 붙여넣기용이라 **인라인 스타일만** 쓴다(`<style>` 블록·외부 CSS 금지).

- 컨테이너 `max-width:600px`, 폰트 `'맑은고딕','Malgun Gothic','Apple SD Gothic Neo',sans-serif`, `font-size:14px`, `line-height:1.8`
- 제목: `[모두의연구소] {기업명} {과정명} 제안서 및 견적서`
- 본문 구성: 담당자 호칭 → 발신자 소개(모두의연구소 김도희) → 첨부 안내 → **과정 요약 1~2문장**(대상·인원·구성·총시간) → 협의 여지 안내 → 인사
- 서명 블록: 이름·소속·이메일·주소, 상단에 `border-top:1px solid #eeeeee`
- 과정 요약은 `content.json`의 확정 내용만 쓴다. 없는 숫자를 만들지 않는다.

## 컴플라이언스 (필수)

`docs/review_compliance_reviewer.md` 기준을 견적서·이메일에도 적용한다.

- 강사 **실명·연락처·이메일**을 넣지 않는다. 필요하면 마스킹(`홍*동`).
- 내부 원가·마진·타 고객사 단가를 노출하지 않는다. 고객에게 나가는 것은 확정 단가뿐이다.
- 중간 협의 이력('수정사항 반영' 등)을 최종본에 남기지 않는다.

## 완료 후

1. 3종 파일 경로를 사용자에게 보고하고, 소계·VAT·총합계를 한 줄로 요약한다.
2. `[협의 필요]`로 남긴 항목이 있으면 목록으로 알린다.
3. 다음 안내: "전체 산출물이 준비되었습니다. 폴더 열어볼까요?"
4. `git add/commit` (기업 폴더 단위).

> 견적서를 PDF로 발행할 때 사내 파일명 규칙은
> `[모두의연구소] 고객사명_과정명_견적서_YYMMDD.pdf` 이다.
> 강사 후보군을 함께 안내하는 별도 메일이 필요하면
> `{기업명}_AI교육_이메일_초안_강사후보군.html` 로 따로 만든다(고객용 본문과 섞지 않는다).
