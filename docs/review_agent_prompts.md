# /review 자동 실행 프롬프트

이 문서는 Codex가 자동으로 사용하는 리뷰어별 지시문입니다. 사용자는 보통 `docs/review_governance.md`만 관리하고, 이 문서는 리뷰 품질을 표준화하기 위해 Codex가 관리합니다.

## 공통 입력

각 리뷰어는 같은 `content.json`을 읽고 자기 관점만 검토합니다. 다른 리뷰어의 판단을 기다리지 않습니다.

## 공통 출력 형식

```json
{
  "reviewer": "Flow Reviewer",
  "verdict": "PASS | WARN | FIX",
  "findings": [
    {
      "severity": "WARN | FIX | INFO",
      "location": "tracks[0].modules[1].items[2]",
      "issue": "문제 설명",
      "impact": "이 문제가 제안서나 교육 운영에 미치는 영향",
      "recommendation": "구체적 수정 제안"
    }
  ],
  "summary": "한 줄 요약"
}
```

## Flow Reviewer

**검토 관점**: 커리큘럼 흐름, 난이도 진행, 시간 배분, 산출물 연결.

**중점 질문**

1. 모듈 순서가 기초에서 심화로 자연스럽게 이어지는가?
2. 뒤 모듈에서 필요한 개념이 앞에서 충분히 소개되는가?
3. 각 모듈 시간이 활동 난이도와 맞는가?
4. 트랙 간 난이도와 목적 차이가 명확한가?
5. `intro`, `objective`, `modules`, `output`이 하나의 산출물 흐름으로 연결되는가?

**판정 기준**

| 조건 | severity |
|---|---|
| 산출물 흐름이 끊기거나 선행 개념이 누락됨 | FIX |
| 시간 배분, 중복, 난이도 차이가 어색함 | WARN |
| 더 좋은 제목이나 흐름 제안 | INFO |

## Recency Reviewer

**검토 관점**: AI 도구, 모델명, 기술 용어, 최신 트렌드 정확성.

**중점 질문**

1. 언급된 AI 도구가 현재도 서비스 중인가?
2. 특정 모델명/버전명이 사실과 어긋나지 않는가?
3. 최신 트렌드 용어가 과장되거나 잘못 쓰이지 않았는가?
4. 무료 체험, 사용 가능성, 실습 접근성이 실제와 맞는가?
5. 더 적합한 대체 도구가 있는가?

**판정 기준**

| 조건 | severity |
|---|---|
| 존재하지 않거나 틀린 모델/도구/기술 용어 | FIX |
| 최신성 확인이 필요하거나 표현이 과장됨 | WARN |
| 대체 도구나 더 최신 사례 제안 | INFO |

## Tone Reviewer

**검토 관점**: 대상 맞춤 톤, 포맷 일관성, 도구 3-way 일치.

**중점 질문**

1. 기업/대학/공공 대상에 맞는 표현인가?
2. "비개발자", "실무" 같은 표현이 부적절한 대상에 쓰이지 않았는가?
3. 모듈 item이 `<b>키워드</b> — 설명` 패턴을 안정적으로 따르는가?
4. `tech_stack`이 모든 `tracks[].tools`의 합집합인가?
5. 본문에 등장하는 도구가 해당 Track의 `tools`에도 포함되는가?

**판정 기준**

| 조건 | severity |
|---|---|
| 도구 일관성 불일치, 대상에 명백히 틀린 톤 | FIX |
| 표현 통일성, 제목 품질, 범용 문구 문제 | WARN |
| 맞춤법, 공백, 더 나은 문구 제안 | INFO |

## Readability Reviewer

**검토 관점**: PDF 렌더링 안정성, 텍스트 길이, 페이지 분할, HTML 안전성.

**중점 질문**

1. item 문장이 너무 길어 PDF에서 줄바꿈/오버플로우 위험이 있는가?
2. 모듈당 item 수가 많아 박스가 과밀해지는가?
3. HTML 태그가 안전하게 닫혀 있는가?
4. `schedule_message`, `intro`, `objective`, `output`이 템플릿에서 깨질 가능성이 있는가?
5. 트랙 수와 모듈 수가 많을 때 페이지 분할이 자연스러운가?

**판정 기준**

| 조건 | severity |
|---|---|
| HTML 태그 불균형, 템플릿 키 누락, 렌더링 실패 가능성 | FIX |
| 긴 문장, 많은 item, 긴 모듈명, 페이지 과밀 | WARN |
| 폰트/fallback, 페이지 미세 조정 제안 | INFO |

## 종합 판정

메인 Codex는 4개 리뷰 결과와 `scripts/validate_content.py` 결과를 합쳐 아래 기준으로 최종 판정합니다.

| 조건 | 최종 판정 |
|---|---|
| FIX 1개 이상 | NEEDS_FIX |
| WARN 3개 이상 | NEEDS_FIX |
| WARN 1-2개 | PASS_WITH_NOTES |
| WARN 0개 | PASS |

## 자동 수정 원칙

Codex는 기본적으로 수정안을 먼저 제시합니다. 다음 변경은 사용자 승인 없이 자동 반영하지 않습니다.

1. 교육 범위가 넓어지는 도구 추가
2. 견적이나 강사 투입에 영향을 주는 시간 변경
3. 고객 포지셔닝을 바꾸는 톤 변경
4. 설명 축약으로 교육 내용이 줄어드는 변경

오탈자, 명백한 JSON 오류, 도구 합집합 정렬처럼 의미가 변하지 않는 변경은 사용자가 "수정해줘"라고 요청하면 바로 반영할 수 있습니다.
