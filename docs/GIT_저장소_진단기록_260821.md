## Phase 1 — 개행(CRLF) 문제 해결 ← 841건의 87%를 없애는 단계

이 단계를 건너뛰면 어떤 파일을 `git add` 해도 **그 파일 전체가 개행 변경으로 커밋**됩니다.

```powershell
# ── 1-1. .gitattributes 확인 — 이미 생성되어 있습니다 (2026-08-21 작성)
#    저장소 루트: C:\Users\Admin\Downloads\ai-education-proposal\.gitattributes
#    실제 추적 확장자 분포를 근거로 작성했습니다:
#      .odttf 153건(Office 임베디드 폰트) → binary 필수. 정규화되면 문서가 깨짐
#      .hwpx / .xlsx / .docx / .pptx / .m4a / .png → binary
#      Office 압축 해제물(word/·_rels/·[Content_Types].xml 약 570건 추적 중) → -text (정규화 금지)
#      .bat / .cmd / .ps1 → CRLF 유지
Get-Content .gitattributes | Select-Object -First 20
git check-attr text eol -- "README.md"        # text: set / eol: lf 확인
git check-attr binary -- "projects/2026 연세대/히스토리/unpacked_v1/word/document.xml"   # -text 적용 확인

# ── 1-2. autocrlf 명시적으로 끄기 (.gitattributes가 우선하도록)
git config core.autocrlf false

# ── 1-3. ⚠️ 최신 main으로 이동해서 정규화 커밋을 올릴 브랜치를 만듭니다
#    현재 브랜치(삼성)는 origin/main보다 33 뒤처져 있어 여기서 하면 충돌이 커집니다.
git fetch origin --prune

# ⚠️ 위험: 브랜치 이동 시 untracked 파일 충돌이 예상됩니다 (A-4 ④ 참조).
#    먼저 비켜둡니다.
$stash = "..\_untracked_backup"
New-Item -ItemType Directory -Force -Path $stash | Out-Null
Copy-Item ".\projects\260720 롯데이커머스 전사교육\롯데이커머스_3트랙_교육과정_소개.html" $stash -Force

# ── 1-4. 이동 전 확인: 무엇이 사라지고 무엇이 남는지 미리 봅니다 (실행 안 함)
git switch main --no-guess 2>&1 | Select-Object -First 20   # 에러 메시지 확인용. 실패해도 정상.
```

> ⚠️ **여기서 멈추고 판단하세요.** `git switch main`이 다음 이유로 실패할 수 있습니다.
> - **untracked 파일 충돌** → 해당 파일을 `$stash`로 옮긴 뒤 재시도
> - **로컬 수정 사항이 덮어써짐 경고** → 그 파일이 삼성 작업물인지 확인. 삼성 작업물이면 **Phase 1을 중단하고 삼성 PR을 먼저 마무리**하세요 (Phase 1-B 참조)

```powershell
# ── 1-5. main 최신화 후 정규화 브랜치 생성
git switch main
git merge --ff-only origin/main        # 35 커밋 따라잡기. ff-only라 이력이 꼬이지 않음
git switch -c chore/gitattributes-eol-normalize

# ── 1-6. 정규화 적용 — 인덱스만 갱신, 파일 내용은 바뀌지 않습니다
git add .gitattributes
git add --renormalize .

# ── 1-7. 확인: 몇 건이 정규화 커밋에 들어가는지
git diff --cached --stat | Select-Object -Last 1

# ── 1-8. 커밋 (기존 커밋 메시지 관례: `chore:` 접두어 사용례 있음)
git commit -m "chore: .gitattributes 도입 및 개행 LF 정규화 (CRLF 노이즈 731건 해소)"
git push -u origin chore/gitattributes-eol-normalize

# ── 1-9. 효과 확인
git status --porcelain | Measure-Object -Line   # 841 → 약 110건으로 감소 예상
```

**되돌리기**: `git switch main; git branch -D chore/gitattributes-eol-normalize` (push까지 했다면 `git push origin --delete chore/gitattributes-eol-normalize`)

## Phase 3 — 브랜치 정리 (선택, Phase 2 완료 후)

```powershell
# ── 3-1. 병합 완료된 로컬 브랜치 목록 확인 (삭제 전 반드시 눈으로)
git fetch origin --prune
git branch --merged origin/main --format="%(refname:short)" | Where-Object { $_ -ne "main" }

# ── 3-2. ⚠️ 위험: 아래는 실제 삭제입니다. 3-1 목록을 확인한 뒤에만 실행하세요.
#    -d 는 병합되지 않은 브랜치를 거부하므로 -D 보다 안전합니다.
git branch --merged origin/main --format="%(refname:short)" |
  Where-Object { $_ -ne "main" } |
  ForEach-Object { git branch -d $_ }

# ── 3-3. 병합 안 된 브랜치 확인 (삭제하지 말고 남겨두거나 개별 판단)
git branch --no-merged origin/main --format="%(refname:short)"

# ── 3-4. 원격에서 이미 사라진 추적 브랜치 정리 (안전)
git remote prune origin
```

> ⚠️ `claude/*` 22개는 Claude Code 자동 생성입니다. 3-1 목록에 있으면 삭제해도 무방하지만, **3-3 목록(병합 안 됨)에 있으면 미병합 작업이 남아 있을 수 있으니 삭제 금지**입니다.
