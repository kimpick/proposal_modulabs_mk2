# 라벨 배지 가이드

제안서·교육안내 PDF에서 항목 옆에 작은 색상 라벨(배지)을 붙여 분류·강조하는 방법을 정리한 카탈로그입니다. 새 프로젝트에서 유사 케이스가 생기면 여기 패턴을 그대로 가져다 쓰세요.

> **전제**: `build.py`는 Jinja `autoescape=False`로 동작하므로, content.json의 문자열 안에 HTML을 직접 임베드하면 그대로 렌더됩니다. 필터 `| safe` 같은 수동 처리 불필요.

---

## 1. 사용 가능한 라벨 시스템

### 1-1. 차수 태그 (`base.css` 정의 — 모든 템플릿에서 사용 가능)

| 클래스 | 의미 | 색상 (배경 / 글자) |
|---|---|---|
| `tag-common` | 공통 | `#F3F4F6` / `#6B7280` (회색) |
| `tag-round1` | 1차 교육 | `#EEF4FF` / `#2563EB` (파랑) |
| `tag-round2` | 2차 교육 | `#FEF0F0` / `#EE3E4C` (모두연 빨강) |

베이스 클래스 `.curriculum-tag`는 `display: inline; font-weight: 600; padding: 1px 5px; border-radius: 3px; margin-right: 4px;` — 인라인 작은 칩.

### 1-2. 콘텐츠 강조 태그 (`templates/proposal_combined.html` 인라인 정의 — 종합 제안서 한정)

| 클래스 | 의미 | 색상 (배경 / 글자) |
|---|---|---|
| `tag-core` | 핵심 | `#FEF0F0` / `#EE3E4C` |
| `tag-trend` | 트렌드 | `#EEF4FF` / `#2563EB` |
| `tag-paradigm` | 패러다임 | `#F5F0FF` / `#7C3AED` |
| `tag-shift` | 전환점 | `#FFF8EB` / `#D97706` |

> 콘텐츠 강조 태그는 현재 `proposal_combined.html` 인라인 CSS에만 있어 다른 템플릿에서는 동작하지 않습니다. 다른 템플릿에서 같은 태그가 필요해지면 `base.css`로 옮기는 것을 검토하세요.

---

## 2. 사용 사례 (When)

| 케이스 | 추천 태그 | 참고 프로젝트 |
|---|---|---|
| 다중 차수 교육에서 차수별 참석자가 다름 → 항목별 차수 구분 | 차수 태그 (`tag-common/round1/round2`) | `projects/현대자동차/피드백 반영_260424/` |
| `tech_stack` 내 도구가 차수마다 다름 — 합집합 표시하면서 어느 차수 도구인지 구분 | 차수 태그 | 동일 |
| `infrastructure` 항목이 차수마다 다름 — 데이터·테스트베드 분리 | 차수 태그 | 동일 |
| 커리큘럼 항목 내 트렌드/핵심/패러다임 강조 | 콘텐츠 강조 태그 | `projects/도쿄일렉트론코리아/` |

차수가 셋 이상(예: 1차/2차/3차)이거나 다른 분류축(예: 직군별)이 필요하면 `base.css`에 새 modifier 클래스를 추가하세요. 색상은 brand `#EE3E4C`와 충돌하지 않는 범위에서 선택.

## 3. HTML 사용 예시

### 3-1. tech_stack (chip 안에 배지 + 도구명)

```json
"tech_stack": [
  "<span class='curriculum-tag tag-common'>공통</span>Python",
  "<span class='curriculum-tag tag-round1'>1차교육</span>LangChain",
  "<span class='curriculum-tag tag-round2'>2차교육</span>OpenClaw"
]
```

`guide.html`에서 `<div class="tech-badge">{{ t }}</div>`로 렌더되어, 둥근 chip 안에 작은 색상 배지가 도구명 앞에 붙는 형태가 됩니다.

### 3-2. infrastructure (li 안에 배지 + 항목)

```json
"infrastructure": [
  "<span class='curriculum-tag tag-common'>공통</span>실습용 노트북 1인 1대",
  "<span class='curriculum-tag tag-round1'>1차교육</span>MS Office 및 Confluence 샘플 데이터 제공",
  "<span class='curriculum-tag tag-round2'>2차교육</span>OpenClaw 실습용 샌드박스 환경"
]
```

### 3-3. 콘텐츠 항목 (도쿄일렉트론 패턴)

```json
"items": [
  "비정형 데이터 파싱 & 시맨틱 청킹 (3H): <span class='curriculum-tag tag-trend'>Trend</span>Vision LLM 기반 PDF 파싱, ..."
]
```

---

## 4. 라벨 텍스트 명명 규칙

- **차수 태그**: 그 프로젝트의 실제 차수 명칭과 일치 (예: "1차교육"/"2차교육", 또는 단순히 "1차"/"2차"). content.json의 `schedule_blocks[].label`과 통일.
- **콘텐츠 강조 태그**: 영문 한 단어 권장 (`Trend`, `Core`, `Paradigm`, `Shift`).
- **공통 라벨**: "공통" 그대로.

---

## 5. 주의 사항

- 데이터에 HTML을 임베드하므로, 같은 항목을 다른 템플릿(예: 견적서·이메일)에서도 재사용하면 거기서는 raw HTML이 그대로 보일 수 있음. tech_stack/infrastructure는 PDF 한정이라 보통 안전.
- 라벨이 너무 많아지면 chip이 과잉 정보가 됩니다. **3종 이내** 권장.
- 라벨 텍스트는 짧게 (한글 4자 이내, 영문 8자 이내) 유지.
- 색상 추가 시 `base.css`에 modifier 클래스로 (`.tag-{이름}`) 정의하고 본 가이드에 추가.
