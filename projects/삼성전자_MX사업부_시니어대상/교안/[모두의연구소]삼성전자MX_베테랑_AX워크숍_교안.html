How We Work

이 워크숍은 이렇게 다릅니다

🚫
도구 설명 강의 없음
ChatGPT가 뭔지, Google AI Studio가 뭔지 긴 설명 없습니다. 내 업무에 어디에 쓸지를 먼저 설계하고, 도구는 그 다음에 씁니다.
✍️
직접 쓰고 만드는 시간
강사가 보여주는 시간보다 참가자가 직접 하는 시간이 더 많습니다. 워크시트, 실습, 발표가 번갈아 진행됩니다.
💡
베테랑 경험이 핵심 재료
수십 년 현업에서 쌓은 경험이 오늘 가장 중요한 재료입니다. 업무 맥락을 AI에 정확히 전달할수록 결과가 달라집니다.
📦
끝나면 산출물 1건 완성
오늘 워크숍 종료 시 대시보드 또는 에이전트 1건을 실제로 완성합니다. "해봤다"가 아니라 "만들었다"로 마무리합니다.

Part 1 · 0.5H

AI 기술 브리핑

지금 AI에서 가장 중요한 변화 2가지

하네스 엔지니어링 · 에이전틱 AI

AI Trend 2026

AI는 이제 "시키는 것"에서
"설계하는 것"으로 바뀌었습니다

🔧
하네스 엔지니어링
AI에게 맥락·제약·역할을 명확히 설계해서 원하는 결과를 안정적으로 얻는 방법론. 단순히 프롬프트를 쓰는 것과 다릅니다.
🤖
에이전틱 AI
AI가 여러 단계를 스스로 연결해서 처리하는 방식. "한 번 물어보는" 챗봇을 넘어, 업무 흐름 전체를 AI가 실행합니다.

핵심 변화: AI를 잘 쓰는 사람과 못 쓰는 사람의 차이는 이제 "설계 능력"에서 납니다.
베테랑의 업무 도메인 지식은 이 설계 능력의 핵심 원재료입니다.

Concept

하네스 엔지니어링이란?

AI를 단순히 "사용"하는 것이 아니라,
AI가 잘 일하도록 환경을 설계하는 것

ROLE (역할)
AI에게 역할 부여
"너는 MX사업부 품질팀 분석가야"처럼 명확한 역할과 전문성 맥락을 먼저 설정합니다.
CONTEXT (맥락)
배경 정보 설계
업무 배경, 관련 데이터, 제약 조건을 AI에게 구체적으로 알려주어 엉뚱한 답변을 방지합니다.
CONSTRAINT (제약)
규칙과 제한 설정
출력 형식, 길이, 금지 사항 등을 명시해서 AI 결과물의 품질을 제어합니다.

Real Case

하네스 엔지니어링 — 실무 사례

방식프롬프트결과
기존 방식 "이 불량 데이터 분석해줘" 일반적인 통계 분석. 실무에 쓰기 어려운 결과.
하네스 방식 "너는 MX 스마트폰 생산라인 품질 분석 전문가야. 지난 분기 불량률 데이터를 보면 트랙2 라인에서 이상이 반복됐어. 원인 가설 3개를 도출하고, 각 가설 검증에 필요한 데이터 항목을 표로 정리해줘." 실제 업무에 바로 쓸 수 있는 가설 분석 + 검증 계획

👉 차이는 도메인 지식입니다. "트랙2 라인", "분기 불량률"이라는 맥락은 베테랑만 알고 있습니다.

Concept

에이전틱 AI란?

챗봇은 질문에 답합니다.
에이전트는 일을 합니다.

챗봇 (기존)
사람이 → 질문 → AI 답변 → 사람이 다시 → 다음 질문 → ...
→
에이전트 (현재)
사람이 → 목표 설정 → AI가 계획 → 단계 실행 → 결과 전달

오늘 실습에서 agent.ai로 실제 업무 에이전트를 만들어봅니다.

Real Case

에이전틱 AI — 제조업 현장 도입 사례

📊
품질 리포트 에이전트
매일 생산 데이터를 수집 → 이상 패턴 탐지 → 담당자에게 자동 요약 리포트 발송. 수동으로 2시간 걸리던 작업이 10분으로.
🔍
경쟁사 동향 모니터링 에이전트

오늘 목표: 내 반복 업무 중 하나를 에이전트로 만들어서, 에이전트가 대신 처리하는 경험을 합니다.

Part 2 · 1H

내 업무 정의하기

AI가 제대로 작동하려면
내 업무 구조를 먼저 알아야 합니다.

Why First

왜 도구보다 "업무 정의"가 먼저인가

AI 도구는 내 업무를 모릅니다.
도구를 먼저 배우면, 이미 알고 있는 기능에만 업무를 끼워 맞추게 됩니다.

❌ 도구 먼저
"ChatGPT로 뭘 할 수 있을까?" → 내 업무 중 ChatGPT에 맞는 걸 찾는다 → 피상적인 활용에 그침
✅ 업무 먼저
"내가 매주 2시간 쓰는 이 작업을 어떻게 줄일까?" → 적합한 AI 도구를 선택 → 실질적인 업무 전환

Framework

업무 정의 프레임워크: 역할 · 입력 · 처리 · 출력

역할 (Role)
이 업무에서 나의 역할은?
예: "생산팀 품질 이슈를 분석하고 개선 방향을 제시하는 역할"
입력 (Input)
무엇을 받아서 처리하는가?
예: "주간 불량률 데이터, 라인별 생산 실적 엑셀 파일"
처리 (Process)
어떤 단계를 거치는가?
예: "데이터 취합 → 이상값 탐지 → 원인 분석 → 보고서 초안 작성"
출력 (Output)
어떤 결과물을 만드는가?
예: "주간 품질 현황 보고서 (PPT 5장 + 핵심 지표 요약)"

Example

업무 정의 예시

예시: 구매팀 시니어 담당자
역할주요 부품 공급사의 납기 리스크를 조기에 탐지하고 구매 전략을 수정하는 역할
입력공급사 주간 리포트, 생산 일정 엑셀, 글로벌 부품 수급 뉴스
처리리포트 검토 → 납기 지연 가능성 예측 → 대안 공급사 검토 → 팀장 보고 자료 작성
출력주간 공급 리스크 요약 + 대응 방안 2~3가지 (매주 월요일 오전)

이 정도로 구체화되면, AI에게 "이 역할을 대신 해줘"라고 설계할 수 있습니다.

Part 3 · 2H

업무 진단 & 페인포인트 발굴

AI 적용 포인트를 찾는 게 먼저입니다.
내 업무의 비효율 구간부터 짚어봅니다.

Framework

업무 진단: 3가지 질문

  1. 반복 — 이 업무에서 매번 똑같이 하는 부분이 있나?
    같은 형식의 보고서, 같은 조건의 데이터 정리, 매주 반복되는 취합 작업
  2. 병목 — 이 업무에서 시간이 가장 오래 걸리는 단계는?
    데이터 수집에 3시간, 보고서 초안 쓰는 데 2시간, 검토 대기에 1일
  3. 비효율 — 이 업무에서 "이걸 왜 내가 해야 하지?"라고 느끼는 부분은?
    단순 취합, 형식 변환, 이미 있는 정보를 다시 요약하는 작업

이 3가지 질문에 답이 나오면, AI 적용 후보가 자동으로 나옵니다.

Part 4 · 1H

AI 전환 시나리오 설계

매트릭스에서 선택한 업무를
AI로 실행하기 위한 설계서를 씁니다.

Design Document

작업 설계서: AI에게 전달하는 업무 명세서

하네스 엔지니어링을 적용해서 AI에게 업무를 정확히 전달하는 문서입니다.

📋 작업 설계서 구성 요소
  • ① 목적: 이 AI가 무엇을 하는가
  • ② 역할: AI에게 부여할 전문가 역할
  • ③ 입력: 어떤 데이터/자료를 줄 것인가
  • ④ 처리 단계: AI가 거쳐야 할 순서
  • ⑤ 출력: 원하는 결과물 형식
  • ⑥ 제약: 하지 말아야 할 것
✅ 잘 쓴 설계서의 특징
  • → AI가 읽어도 업무를 이해할 수 있다
  • → 출력물 품질을 예측할 수 있다
  • → 다른 사람도 같은 결과를 재현할 수 있다
  • → 도메인 지식이 명확하게 반영돼 있다

Example

작업 설계서 예시

작업 설계서 — 주간 공급 리스크 요약 에이전트

목적: 매주 월요일 오전 8시, 주요 공급사 납기 리스크를 자동 요약하고 팀에 공유

역할: 너는 MX사업부 구매팀의 공급망 리스크 전문 분석가야.

입력: 공급사 주간 리포트 PDF + 생산 일정 엑셀 (월요일 7시 자동 수신)

처리: 1) 납기 지연 가능성 탐지 → 2) 영향받는 생산 라인 확인 → 3) 대안 공급사 가용 여부 체크 → 4) 요약 작성

출력: 리스크 요약 3줄 + 주의 공급사 목록 표 + 권장 액션 2가지 (500자 이내)

제약: 확인되지 않은 수치는 [미확인]으로 표기. 내부 원가 정보는 포함하지 않음.

Step 1 · agent.ai — 연동 설정

에이전트 만들기 (2/2): ChatGPT & 스프레드시트 연결

agent.ai — Integrations

ChatGPT 앱 연동

Step 2 · Google AI Studio — 대시보드 제작 (1/2)

스프레드시트 연결 & 대시보드 생성

aistudio.google.com

1aistudio.google.com 접속 → Google 계정 로그인 → "New prompt"

2모델: Gemini 2.0 Flash 선택 (기본값 유지)

3우측 상단 "Add file" → agent.ai가 쌓은 스프레드시트 파일(CSV 다운로드)을 업로드
스프레드시트 → 파일 → CSV 다운로드 → 업로드

4아래 프롬프트 입력

위 데이터는 [업무 에이전트]가 처리한 결과물입니다.
이 데이터를 분석해서 HTML 대시보드를 만들어줘.
보여줄 항목: [핵심 지표 2~3가지 — 예: 처리 건수, 리스크 레벨, 처리 시간]
형식: 차트 + 요약 수치 + 핵심 인사이트 1줄
색상: 파란색 계열, 깔끔한 비즈니스 스타일
완전한 HTML 코드로 출력해줘.
💡 샘플 데이터가 없으면: 강사가 공유하는 실습용 CSV 파일 사용

Step 2 · Google AI Studio — 대시보드 제작 (2/2)

대시보드 저장 & 수정하기

aistudio.google.com — 대시보드 생성 완료

1생성된 HTML 코드 전체를 복사

2메모장(메모장.exe) 열기 → 붙여넣기 → 파일명.html로 저장

3저장한 .html 파일을 Chrome으로 열어서 결과 확인

4수정이 필요하면 Google AI Studio 채팅창에 바로 추가 요청

수정 예시:
"차트를 막대 그래프로 바꿔줘"
"핵심 수치를 더 크게, 강조색으로 만들어줘"
"인사이트 요약을 맨 위에 배치해줘"
"전체 배경을 흰색, 텍스트는 진하게 바꿔줘"

Troubleshooting

막혔을 때 체크리스트

🤖
에이전트 답변이 엉뚱할 때
System Prompt의 역할이 명확한가요? "너는 [직무] 전문가야"로 역할을 더 구체적으로 지정하고, 출력 형식을 예시로 보여주세요.
🔗
스프레드시트 연동이 안 될 때
스프레드시트의 공유 설정을 "링크 있는 사람 편집 가능"으로 변경 후 다시 시도해보세요. Google 계정 권한 문제일 수 있습니다.
📊
대시보드 레이아웃이 이상할 때
"차트를 상단에, 수치를 크게 배치해줘" 처럼 레이아웃을 말로 지정하세요. 완성된 코드에서 바로 수정 요청이 가장 빠릅니다.
🔄
전체 흐름이 연결 안 될 때
각 Step을 순서대로 분리해서 확인하세요: 에이전트 단독 동작 → 스프레드시트 저장 확인 → 그 파일로 대시보드 생성 순으로 진행합니다.
