## 5. 교육 내용 요구

- **핵심 서사** — "문서를 먼저 고치고, 그 문서로 에이전트를 만든다": 업무 문서를 **LLM Wiki**(Karpathy 패턴) + **Google OKF** 규격으로 재편 → 지식그래프 → 하네스(폴더 구조·AGENTS.md·메모리·스킬·훅) → 업무 자동화. **모두연이 미팅에서 제시해 고객이 긍정**한 축입니다.
- **하네스 3축** — Context / Constraints / Entropy (이 고객사 전용 언어로 정착된 프레임워크)
- **도구 (제안 단계)**: Claude / Codex / Antigravity 데스크탑 앱, Gemini — API 아님, **계정 로그인 방식**
- **도구 (파일럿 실제 확정)**: ⚠️ **Claude 데스크톱 앱 · Code 탭 1종으로 통일**. 앱에 탭이 3개인데 로컬 파일 접근은 Code 탭에서만 가능. 로컬 파일 완결 · 외부 서비스 연동 없음 [출처: 석진희 강사 커리큘럼 docx §1]
- **토큰 관리 노하우**를 모듈마다 보충 설명으로 추가 (정성인 프로의 토큰 절감 요청과 연결) [출처: 동일, 서두]
- **하네스 구성 실습 최소 6시간 확보**, 환경 설정 포함 1일 8시간 편성
- **루브릭을 배정 도구로 사용** — 고객이 "현재 수준 파악이 안 된다"고 했으므로 파일럿을 *수준 실측* 목적으로 재정의. 5축 × 4레벨 결과로 기초/심화 배정 + 차수 편성. **개인 등급이 아니라 차수 설계용 집계 데이터**로 명시해 사내 민감도를 회피
- **여러 과정을 종합 제안서 1본에 다트랙으로 통합** — 고객이 "로드맵이 보이도록" 요구
