# 📖 삼성전자 에이전틱 코딩 교육 — 하네스 엔지니어링(Harness Engineering) 전문 용어집 (내부 공유용)

해당 문서는 삼성전자 4, 5월 에이전틱 코딩 교육에 도입되는 OpenAI의 **'하네스 엔지니어링(Harness Engineering)'** 패러다임과 관련된 핵심 전문 용어를 영업 및 기획 내부 공유용으로 알기 쉽게 정리한 문서입니다.

---

## 1. 기반 패러다임 용어

### 🔹 하네스 엔지니어링 (Harness Engineering)
* **정의:** AI 에이전트가 자율적으로 코드를 작성하고 업무를 수행할 수 있도록, **'올바른 환경과 작업장(Harness)'을 설계하고 통제하는 새로운 소프트웨어 공학 분야**입니다.
* **핵심 철학:** *"에이전트를 똑똑하게 만드는 것보다, 에이전트가 오작동하지 않는 환경을 구축하는 것이 더 어렵고 중요하다."* (Agents aren't hard; the Harness is hard.)
* **교육 적용점:** 단순 채팅형 지시를 넘어, 에이전트가 일할 수 밖에 없는 구조(컨텍스트, 제약, 데이터 정비)를 짜는 '아키텍트'로서의 역량을 기릅니다.

### 🔹 에이전틱 코딩 (Agentic Coding)
* **정의:** 개발자가 직접 코드를 한 줄씩 입력하는 대신, 자동화된 AI 에이전트(Agent)가 독립적으로 코드를 작성, 테스트, 배포하도록 시스템을 조율하는 코딩 방식입니다.

### 🔹 바이브 코딩 (Vibe Coding)
* **정의:** 시스템적인 명확한 제약 없이, AI에게 느낌(Vibe)대로 대충 설명하고 AI가 짜준 코드를 눈치껏 복붙하며 수정하는 비체계적인 개발 방식입니다. (하네스 엔지니어링 도입 이전 단계)

---

## 2. 하네스 3대 핵심 요소 (Context, Constraints, Entropy)

### 🔹 컨텍스트 엔지니어링 (Context Engineering)
* **정의:** 에이전트가 올바른 결정을 내릴 수 있도록 '필요한 지식, 사내 규정, 과거 코드 내역이나 히스토리'를 사전에 깔아주는(주입하는) 작업입니다.
* **적용 예시 (개발):** `.cursorrules`, `AGENTS.md` 파일에 개발 가이드 작성.
* **적용 예시 (비개발):** 사내 RAG 문서 분류 체계 정립, 참조할 가이드라인 폴더화 구축.

### 🔹 구조적 제약 (Architectural Constraints)
* **정의:** AI 에이전트가 이탈(Hallucination 등)하거나 나쁜 코드를 짜지 못하도록, 억지로 가둬놓는 **'강제적인 울타리(가드레일)'**입니다.
* **적용 예시 (개발):** 린터(Linter) 규칙 적용, 테스트 주도 개발(TDD) 강제, 코드 리뷰 통과 시에만 PR 허용(자동화 파이프라인).
* **적용 예시 (비개발):** 규격화된 엑셀/워드 템플릿 사용 강제화, SOP(표준 운영 절차) 정의에 따른 순차적 단계 실행 지시.

### 🔹 엔트로피 관리 (Entropy Management / 복잡도 통제)
* **정의:** AI 에이전트가 많은 코드를 생성할수록 시스템이 엉키고 복잡해지는 현상(엔트로피 증가)을 막기 위해, 불필요한 코드를 청소(Garbage Collection)하고 코드를 리팩토링하는 유지보수 루프입니다.
* **적용 예시:** 주기적으로 에이전트에게 "기존 코드/문서 구조 정리 및 리팩토링"을 명령하는 정기 파이프라인.

## 3. 관련 기술 및 응용 용어

### 🔹 SOP (Standard Operating Procedure / 표준 운영 절차)
* **정의:** 복잡한 업무를 누구나 동일하게 처리할 수 있도록 정해둔 표준화된 순서와 지침. 5월 비개발자 과정에서 **AI 에이전트에게 내릴 '비즈니스 제약(Business Harness)'의 핵심 룰셋**으로 작용합니다.

### 🔹 환각 (Hallucination)
* **정의:** AI 시스템이 학습되지 않았거나 부정확한 사실을 그럴듯하게 지어내는 현상. 
* **해결책:** 강력한 **제약(Constraints)**과 확실한 **컨텍스트(Context)**를 하네스 시스템으로 제공해야 이를 억제할 수 있습니다.

### 🔹 PR (Pull Request / 코드 병합 요청)
* **정의:** 새로운 코드를 메인 코드베이스에 합쳐 달라고 요청하는 행위. 하네스 엔지니어링에서는 AI가 스스로 PR을 만들고, 또 다른 검증 에이전트가 이를 자동 리뷰하는 파이프라인을 구축합니다.

### 🔹 CI/CD (지속적 통합 및 배포)
* **정의:** 코드 빌드, 테스트, 배포를 자동화한 시스템. 하네스 엔지니어링 환경에서 CI/CD는 AI의 나쁜 코드가 서버로 실서버로 넘어가는 것을 막는 핵심 '제약(Constraint)' 장치입니다.
