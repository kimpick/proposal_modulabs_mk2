## 결정과 근거

- **결정**: 오프닝세션은 실습 없이 전략 관점 + 강사 시연
  **왜**: 2시간에 53명 대상 기술 실습은 비효율 / **출처**: 김영광 연구원 의견 → 고객 수용 (8/11)
- **결정**: 본교육 3~4회차 AI 활용을 온톨로지·지식 그래프 → 자동화·대시보드 흐름으로 설계
  **왜**: 범용 프롬프트 실습이 아니라 사내 문서·데이터의 관계망을 만들어 자동화로 연결해야 "부서별 과제 방향성 설정" 목표에 닿음. 3회차 산출물(지식 그래프)을 4회차가 소비하는 연결 구조 / **출처**: 김영광 연구원 초안 (8/12)
- **결정**: 3~4회차 실습은 **Claude Code·LLM 위키 기반 적극 수준**으로 설계
  **왜**: 지식 그래프를 실제로 만들고 그것을 자동화·대시보드로 소비해야 학습 효과가 남음. 채팅 기반 축소안은 사내망 불가 회신 시의 대안으로만 준비 / **출처**: 김영광 연구원 결정 (8/12)
- **결정**: 제안서 도구 표기는 **Copilot·Claude만 명시**, Claude Code·LLM 위키는 "Claude 기반 지식 그래프 구축 환경"으로 일반화
  **왜**: 비개발자 53명 대상이라 도구명이 진입장벽으로 읽힘. **표기와 실제 운영 기준이 다르므로 강사와 사전 정렬 필요** / **출처**: 김영광 연구원 결정 (8/12)
- **결정**: 온톨로지를 전면 타이틀로 내세우지 않고 "AI 활용 파트의 수단"으로 배치
  **왜**: 고객이 데이터 레이크·통계분석 중심으로 방향 전환을 요청한 이력 / **출처**: 기획요건 컨텍스트 §3

- **결정**: 지식 그래프 실습 산출물을 "부서 단위 지식 그래프 1종" → **"초안 1종(개체·관계 정의표 + 관계도)"** 으로 하향
  **왜**: 사내망 Claude·Copilot 채팅 인터페이스로 50분에 만들 수 있는 범위는 개체·관계 추출 결과물까지이고, 쿼리 가능한 그래프 DB는 별도 저장소·파이프라인이 필요. 고객 검수에서 지적받을 문장이었음 / **출처**: 최신성 검토 (8/12)
  → 같은 이유로 "자동화"도 스케줄링 자동 실행이 아니라 **반복 가능한 절차**로 표현 조정
- **결정**: PDF 7페이지 레이아웃 수용 (트랙이 페이지 경계에 걸침)
  **왜**: 검토에서 보강한 기술 내용(레이크하우스·클래스 불균형·GraphRAG·에이전트 도입 조건)을 유지하는 쪽을 택함. `.track-heading`에 강제 page-break를 주는 프로젝트 base.css를 실제로 시험했으나 9페이지 + 빈 페이지가 생겨 폐기. 현재 페이지 넘김은 모두 모듈 카드 경계이고 잘림·고아 헤딩 없음 / **출처**: 가독성 검토 + 검증 (8/12), 사용자 승인
