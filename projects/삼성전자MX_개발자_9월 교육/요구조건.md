## 2. 고객 니즈 (구두 전달 원문 취지)

> "앞으로 **AIOps나 LLMOps**가 중요해질 것 같다. 포인트는 **AI가 일하는 걸 관리할 수 있는 역량**이다."

### 니즈 해석

고객이 말한 "AI가 일하는 걸 관리한다"는 두 축으로 분해됩니다.

| 니즈 축 | 필요 역량 | 대응 도구 |
|---|---|---|
| AI가 **어떻게 일할지 미리 설계**한다 | Graph Engineering — 제어 구조·상태·종료조건 설계 | LangGraph |
| AI가 **실제로 어떻게 일했는지 보고 고친다** | Observability & Evaluation — 트레이스·평가·회귀 | Langfuse |

→ **"설계(Graph) → 실행 → 관측(Trace) → 평가(Eval) → 개선"의 닫힌 루프를 하루에 한 바퀴 완주**시키는 것이 과정의 실질 목표. 이 루프가 곧 AgentOps/LLMOps의 최소 단위.

## 3. 제안 방향 (사내 검토 결과)

### 3.1 과정 구성

| 구분 | 과정명(안) | 시간 | 성격 |
|---|---|---|---|
| **선행** | Agent 기초 — 도구를 쓰는 AI 만들기 | 8H (1일) | Tool Calling · Pydantic 구조화 출력 · 단일 에이전트 |
| **본과정** | Graph Engineering 실전 — LangGraph 멀티에이전트 설계와 Langfuse 관측·평가 | 8H (1일) | 설계→관측→평가 루프 완주 |

**연결 설계**: 선행 과정 미니 프로젝트에서 만든 **단일 에이전트가 본과정에서 그래프의 워커 노드로 그대로 투입**됩니다. 2일 구성의 핵심 강점.

### 3.2 기술 스택 (안)

| 레이어 | 채택 | 근거 |
|---|---|---|
| 오케스트레이션 | **LangGraph 1.x** | 2026년 프로덕션 채택 1위. 체크포인트·`interrupt()` HITL·타임트래블이 "관리 역량"과 1:1 대응 |
| 관측·평가 | **Langfuse** | OSS **self-host 무료·무제한** → 사내망 환경에서 교육 후 실제 도입 가능. OTel 기반 |
| 구조화 출력 | Pydantic v2 | State·툴 스키마의 토대 |
| 언어/환경 | Python, uv | — |

**제외 결정**: CrewAI(프로덕션 관측·에러복구 취약, 이번 니즈와 상충), RAG/벡터DB(별도 과정), MCP 실습(개념 언급만), Docker/파인튜닝.

### 3.3 커리큘럼 초안 (본과정 8H)

| 모듈 | 시간 | 내용 |
