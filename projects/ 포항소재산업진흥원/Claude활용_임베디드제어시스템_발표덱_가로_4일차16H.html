임베디드 개발 실무자를 위한
Claude 활용 제어시스템 개발

센서와 RS-485 통신을 AI와 함께 개발하고, 제공 GUI로 연결해 End-to-End로 완성합니다.
현장 적용 가능한 제어시스템을 완성하는 4일 압축 실전 과정입니다.

01 / 배경

배경과 문제 인식

임베디드 개발에서 AI 코딩 도구의 한계 요인

병목은 모델 성능보다 모델을 둘러싼 시스템에 있습니다. 2026년 엔지니어링 현장의 공통된 진단입니다.

가장 어려운 과제는 이제 환경과 피드백 루프, 제어 시스템을 어떻게 설계하느냐에 몰려 있다.
— OpenAI 엔지니어링 팀. martinfowler.com「Harness engineering for coding agent users」에서 인용
매번 처음부터 설명
핀맵, 레지스터, 보드 제약을 대화할 때마다 다시 알려줘야 합니다
실행 후에만 확인 가능
컴파일은 통과해도 실제 보드에서 타이밍과 통신이 깨집니다

빌드·업로드·로그 확인을 담당자가 매번 직접 수행합니다

02 / 관점

과정의 뼈대

하네스 · 루프 — 16H 과정의 두 축

프롬프트와 컨텍스트 다음 단계로 자리 잡은 실천을 임베디드 개발 과제에 대응시켰습니다. 4일 과정에서는 앞의 두 단계를 현업 적용 가능한 수준까지 다룹니다.

STEP 1 · HARNESS
하네스 엔지니어링
에이전트에서 모델을 뺀 나머지 전부를 뜻합니다. 미리 방향을 잡아주는 가이드와, 결과를 관측해 스스로 고치게 만드는 센서로 나뉩니다.
STEP 2 · LOOP
루프 엔지니어링
반복 횟수와 중단 시점, 실패 시 복구 방식을 정합니다. 대부분의 실패는 완료 조건이 불명확한 데서 발생합니다.
STEP 3 · GRAPH 후속 과정
그래프 엔지니어링
여러 에이전트를 지휘자와 작업자로 나눠 맡기는 층입니다. 32H 확장 과정의 범위이며, 이번 4일 과정에서는 다루지 않습니다.
임베디드에서 가장 어려운 것은 "제대로 동작하는지 확인하는 일"입니다.
코드가 컴파일되고 테스트를 통과해도 실제 보드에서는 타이밍이 어긋나고 통신이 끊깁니다. 이 과정은 실장비를 연동한 자동 검증 루프(HIL)를 커리큘럼의 중심에 두었습니다.

구성 근거

  • 개발 방식 중심 구성입니다. 수강생이 AI 도구 사용 경험을 갖추고 있어 기초 사용법에 시간을 배분하지 않습니다.
  • 검증 시간을 충분히 배분했습니다. 임베디드에서 AI 코딩이 어긋나는 지점은 대개 하드웨어 검증 구간입니다.
  • 잔존 자산을 사전 설계했습니다. 4일차에 하네스를 템플릿으로 정리해 다음 프로젝트로 연결합니다.
