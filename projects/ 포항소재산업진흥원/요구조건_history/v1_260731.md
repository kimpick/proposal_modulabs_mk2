## 1. 발단

강사 구인이 진행 중이었으나 지원이 더뎌, **커리큘럼을 먼저 설계**해 공고를 구체화하기로 함. 즉 이 건의 1차 목적은 제안서이면서 동시에 **강사 구인 공고 보완**임.

### 원 구인 공고 (원문 요지)

**[주강사 구인] Claude 활용 임베디드 제어시스템 개발 교육**

- 대상 — 임베디드 개발 실무자 (사내 ESP32 개발 경험자 포함)
- 일정 — 하루 4시간 다차수, 커리큘럼 제안 후 총 시간 조율 예정
- 교육 목표
  - Claude를 활용해 임베디드 제어시스템을 개발하는 역량 습득
  - Claude Code 기반 바이브 코딩으로 센서, RS-485 통신, GUI를 AI와 함께 개발
  - 학습한 내용을 현장에 바로 적용하고 테스트할 수 있는 실전형 결과물 확보
- 교육 내용 — Claude/Claude Code 활용 임베디드 제어시스템 개발 실습, AI 협업 기반 센서 연동, RS-485 통신 구현, GUI 개발
- 비용 — 협의를 통해 확정
- 강사 자격
  - 필수 : 임베디드 제어시스템 개발 실무 경험 / ESP32 등 MCU 개발 경험 / Claude Code 등 AI 코딩 도구 활용 개발 경험 / 센서·RS-485·GUI 개발 경험
  - 우대 : 임베디드 분야 강의 경험 / 현장 적용형 실습 설계 경험
- 차수별 세부 커리큘럼은 고객사와 협의하여 확정 (제안 기반)

## 2. 확정된 요구조건

| 항목 | 확정 내용 | 확정 경로 |
|---|---|---|
| 총 차수 | **8차수 × 하루 4시간 (32H)** | 사용자 선택 (5/8/10 중) |
| 실습 환경 | **고객사 실제 설비 연동** — 사전 환경 조사 필요 | 사용자 선택 (실물 키트 / 실물+시뮬 / 실설비 중) |
| 최종 산출물 | **센서 → RS-485 → GUI 통합 모니터링 시스템** | 사용자 선택 (통합시스템 / 개인 현업과제 / 팀 자유주제 중) |
| 수강생 AI 숙련도 | **일부 실무 적용 경험 있음** — 온보딩 생략, 바로 임베디드 특화 워크플로우 진입 | 사용자 선택 |
| 추가 교육 주제 | **harness / loop / graph engineering** 을 과정에 녹일 것 | 세션 중 추가 요청 |
| 제안서 형태 | 16:9 가로 슬라이드 덱 (발표용) | `/proposal-deck-landscape` 스킬 호출 |
| 고객사 표기 | **비공개 (범용)** — 「기업교육」으로 중립 표기 | 사용자 선택 |
| 견적 | **제외** — 커리큘럼 확정 후 별도 견적서로 진행 | 사용자 선택 |
| 문서 톤 | 폰트 확대(발표 가독성), 번역체 제거 | 사용자 피드백 |

## 3. 아직 확정되지 않은 것

교육 착수 전에 고객사와 확정해야 하는 항목. 제안 덱 12번 슬라이드에도 동일 내용이 실려 있음.

| 협의 항목 | 정해야 하는 이유 |
|---|---|
| 대상 설비·레지스터 맵 | 5차수 실연동 범위와 회귀 시나리오를 정하는 기준 |
| 실습 보드·센서 수량 | 팀 편성 인원과 실습 단위(1인/1팀) 결정 |
| 설비 접근 가능 시간 | 5·7차수 실연동과 연속 운전 테스트 일정 배치 |
| GUI 스택 선택 | PySide6 데스크톱이냐 웹 대시보드냐에 따라 6차수 실습이 달라짐 |
| Claude Code 사용 정책 | 사내망에서 쓸 수 있는지, 코드 반출 범위는 어디까지인지 |
| CI 파이프라인 사용 여부 | 3·5차수 회귀 루프를 어디까지 자동화할지 결정 |

추가로 **내부에서** 정해야 할 것:

- 고객사명 공개 여부 및 표지 표기 확정
- 견적 (시간당 단가, 보조강사 여부, 재료비 범위)
- 주강사 확정 및 6차수 GUI 분리 여부
