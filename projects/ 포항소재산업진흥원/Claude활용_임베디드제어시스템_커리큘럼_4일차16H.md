## 설계 축 — 임베디드 실무 × AI 협업 개발

이 과정은 두 축을 겹쳐서 진행합니다. 한 축은 센서에서 RS-485를 거쳐 GUI로 흐르는 데이터, 다른 축은 하네스에서 검증 루프로 올라가는 AI 협업 개발 성숙도입니다.

| 축 | 1일차 | 2일차 | 3일차 | 4일차 |
|---|---|---|---|---|
| 임베디드 | 환경 구축 | 센서 | RS-485 · Modbus | 통합 · GUI |
| AI 협업 | 가이드(하네스) | 검증 루프 | 통신 검증 | 자산화 |

### 개념 정의 — 하네스 · 루프 (2026년 현재 통용 기준)

**하네스 엔지니어링** — 에이전트에서 모델을 뺀 나머지 전부를 가리킵니다(Agent = Model + Harness). 코딩 에이전트를 쓰는 입장에서는 두 가지로 나뉩니다.

- **가이드(feedforward)** : 행동하기 전에 방향을 잡아 주는 규칙·문서·스크립트
- **센서(feedback)** : 행동한 뒤 결과를 관측해 스스로 고치게 만드는 신호

각각 다시 **계산형**(컴파일러·정적분석·테스트 — 결정적이고 빠름)과 **추론형**(리뷰 에이전트, LLM 판정 — 느리고 비결정적)으로 나뉩니다.

**루프 엔지니어링** — 에이전트가 반복하는 주기를 설계하는 일입니다. 한 번에 무엇을 할지, 언제 다시 돌릴지, **무엇을 끝난 것으로 볼지**, 막히면 어떻게 복구하거나 사람에게 넘길지를 정합니다. 실패는 대부분 완료 조건이 불명확한 데서 발생합니다.

> 16H 과정의 범위는 하네스와 루프까지입니다. 여러 에이전트를 조직으로 나누는 **그래프 엔지니어링**은 v1(32H)의 범위이며 이번 과정에서는 제외합니다.

### 임베디드 적용에서의 중요성

임베디드 코드는 컴파일 성공만으로 정상 동작을 판단할 수 없습니다. 핀맵, 전압, 센서 타이밍, 통신 규격, Timeout, 인터럽트와 실제 장비 응답을 함께 확인해야 합니다. Fowler도 하네스 중에서 **"기능이 의도대로 동작하는가"를 검증하는 부분**을 가장 미해결 영역으로 지적합니다. 이 과정은 **실장비를 연동한 자동 검증 루프(HIL)** 를 커리큘럼의 중심 뼈대로 두었습니다.

### 교육 원칙

- AI가 생성한 코드를 검토 없이 반영하지 않습니다.
- 데이터시트와 실제 로그를 근거로 수정합니다.
- 국소적인 오류를 고치기 전에 전체 구조와 영향 범위를 먼저 확인합니다.
- 수정 전후 동작을 비교해 회귀 오류를 막습니다.
- 최종 변경 내용은 개발자가 검토하고 승인합니다.

## 설계 의도

**1) 통합 목표 기준 역순 설계**
센서 → RS-485 → GUI 순서가 그대로 데이터가 흐르는 순서입니다. 앞 일차 결과물이 다음 일차의 입력이 되므로, 4일차에는 별도 조립 없이 시스템이 완성됩니다.

**2) AI 협업 개념의 실무 시점 배치**
하네스와 루프를 별도 일차로 묶으면 현업과 분리된 내용으로 남습니다. 각 개념이 실제로 필요해지는 시점에 배치했습니다. 가이드는 프로젝트를 처음 열 때(1일차), 검증 루프는 첫 드라이버를 확인할 때(2일차) 등장하고, 3일차 통신 검증에서 같은 방식을 다시 적용합니다.

**3) 검증 시간 확보**
생성된 코드의 하드웨어 실동작을 확인하는 시간을 일차마다 배정했습니다. 임베디드에서 AI 코딩이 어긋나는 지점은 대개 이 구간입니다.

**4) 과정 종료 후 잔존 자산**
과정이 끝나면 코드뿐 아니라 **하네스 템플릿**(CLAUDE.md + 검증 스크립트 + 반복 루프)이 남습니다. 이후 사내 임베디드 프로젝트에 그대로 적용 가능한 형태로 4일차에 정리합니다.

**5) 착수 전 확정 항목**

| 협의 항목 | 정해야 하는 이유 |
|---|---|
| 대상 설비·레지스터 맵 | 3일차 Modbus 실습 범위와 회귀 시나리오를 정하는 기준 |
| 실습 보드·센서 수량 | 팀 편성 인원과 실습 단위(1인/1팀) 결정 |
| 설비 접근 가능 시간 | 3·4일차 실연동 구간을 넣을 수 있는지 판단 |
| 제공 GUI 뷰어 사양 | 데이터 포맷과 표시 항목을 사전에 맞춰야 4일차 연동이 바로 진행됨 |
| Claude Code 사용 정책 | 사내망에서 쓸 수 있는지, 코드 반출 범위는 어디까지인지 |
| 사전 준비 범위 | 개발환경 설치를 사전 과제로 돌리면 1일차 실습 시간을 확보할 수 있음 |

| 필수 | RS-485 물리계층과 Modbus RTU 구현 경험 (라이브러리 적용 수준을 넘는 구현) |
| 필수 | Claude Code 같은 에이전틱 코딩 도구로 실제 펌웨어를 짜고 디버깅해 본 경험 |
| 필수 | 임베디드 자동화 검증(유닛테스트·HIL) 구성 경험 — 2·3일차의 핵심 |
| 선택 | Python 계측 GUI 연동 경험 (제공 뷰어 사용 기준, 개발 경험은 불필요) |
| 우대 | 산업 현장 설비 연동 프로젝트 경험 |

**공고 문구 보완 제안** — "AI 코딩 도구 활용 경험"만 기재하면 지원자가 적합성을 판단하기 어렵습니다. "에이전트에게 제공할 가이드와 검증 장치를 직접 설계한 경험", "빌드–업로드–검증을 자동 반복하는 루프를 구성한 경험"처럼 행위 단위로 기재하면 지원 정확도가 높아집니다.
