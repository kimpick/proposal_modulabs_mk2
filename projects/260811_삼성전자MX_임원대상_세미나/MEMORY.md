## 결정과 근거

- **결정**: 핵심 프레임을 3원칙 **측정 · 절감 · 재사용**으로 확정. 부제는 임원이 바로 알아듣는 말로 — ① 얼마 남았는지 먼저 본다 ② 같은 일을 짧게 끝낸다 ③ 한 번 만들어 계속 쓴다
  **왜**: 회의에서 나온 "토큰 + 세션 관리 + 컨텍스트 관리 3축"을 임원이 30분 안에 기억할 수 있는 동사형 3단어로 압축. 세션 관리는 ②, 반복 지시 등록·모델 구분은 ③에 흡수됨
  **출처**: 2026-08-13 설계 협의

- **결정**: 작업별 모델·이용 방식 선택(회의록의 멀티에이전트 활용법)을 별도 축이 아니라 **③ 재사용 하위**에 배치
  **왜**: "한 번 정해두고 계속 쓴다"는 성격이므로 재사용과 같은 범주. 3요소를 넘기면 30분에 전달되지 않음
  **출처**: 동일

  **왜**: 실제 통증이 "월말 소진으로 업무 중 도구를 못 씀"이고, 크레딧이 1일 리셋 구조라 절대 비용이 아니라 배분이 문제

  **출처**: 회의록 260812 Key Decisions

- **결정**: **불확실 수치를 3층으로 분리한다.** ① 공개 대체값이 있는 항목(모델별·이용 방식별 배수)은 근거표 공개 수치를 표기하고 "공개 자료 기준 · 사내 환산 비율 확인 후 교체" 각주 ② 사내 전용·대체 불가 항목(Tier 절대 크레딧)은 잔량 비율 구간으로 재구성 ③ 값이 아닌 구조는 페이즈로 분리. 슬라이드 기입란은 제거하고 배포물로 이동
  **왜**: 미확보 항목이 한 부류가 아니었다. `커리큘럼_초안_v1.md`가 이미 "작업당 5배에서 30배"를 고객에게 공개했으므로 덱이 초안보다 덜 정량적이 되는 모순을 없애야 했다. 기입란 제거 근거는 실습이 없고 해당 세그먼트가 4분이라 관객 기입 시간이 물리적으로 없음
  **출처**: 2026-08-13 ralplan 설계 결정 (계획 v3 ADR-001)

- **결정**: **구조 노출도 기반 페이즈 분리.** Phase 1에서 구조 비노출 산출물만 만들고, 구조 노출분(원칙 슬라이드 조직 차원 우측단·도입부 연결 문장·마무리 목적)은 고객 회신 후로 미룬다. 원칙 슬라이드 우측단은 **빈 컨테이너**로 둬 손실 상한을 고정
  **왜**: 미확정 5건 중 3건은 값(셀 교체)이지만 2건은 **구조**다 — 임원의 조직 단위 열람 권한(`요구조건.md:98`)과 앞뒤 세션 구성(`:99`). 값과 구조는 재작업 비용이 다르다. 원 결정은 이 구분을 하지 않아 저비용 항목까지 함께 유보했고, 확정 시점에 기한이 없어 일정 리스크 전량을 8/29 직전으로 이월했다
  **수용 손실 (사전 승인)**: `:98`이 부정되면 원칙 슬라이드 3장의 우측단을 폐기하고 1단으로 전환한다. `.split`이 `1.2fr/0.8fr`이라 좌측이 전폭으로 리플로우되어 **가독성 재측정 비용은 남는다**. `:99`가 중복을 만들면 도입부·마무리 문구를 재작성한다. 반대로 `:98`이 긍정으로 오면 빈 컨테이너 3개를 무축소 정책 아래 채워야 하므로, 슬라이드별 잔여 추가 예산을 Phase 1 산출물에 기록해 둔다
  **출처**: 2026-08-13 ralplan 설계 결정 (계획 v3 ADR-002)

- **결정**: **가독성 게이트 = 어떤 슬라이드도 축소되지 않는다.** 판정은 모든 `.fit-content`의 computed transform이 `none` 또는 scale ≥ 0.999. 컴포넌트별 폰트 하한표는 쓰지 않는다. 위반 시 폰트를 키우지 않고 **내용을 줄인다**
  **왜**: 발표덱 템플릿의 자동 축소 함수는 축소 전용이라(확대 분기 없음) 하한을 참조 덱 토큰과 같게 두면 하한 검사가 "축소되지 않았는가"와 동일 명제가 된다. 즉 하한표는 판별력이 0이고 인라인 축소 오버라이드를 오탐한다. 헤드리스 측정으로 최밀도 슬라이드가 624/720(여유 96px)로 통과함을 확인했다
  **출처**: 2026-08-13 ralplan 설계 결정 (계획 v3 ADR-003)

- **결정**: **조직 차원을 「리더가 정할 것」과 「시스템 열람이 필요한 것」 두 층으로 나눈다.** 리더 층(팀 하루 사용 기준 합의·점검 자리 정례화·티어 재배분 근거 축적·공용 기본자료 담당자와 기한 지정·기본 모델 표준 등급 권장·역할 분담)은 권한과 무관하게 지금 채운다. 시스템 층(부서·개인별 소모 현황, 도달 알림 설정)만 열람 범위 회신 후로 남긴다
  **왜**: 조직 차원 전체가 `요구조건.md:98` 열람 권한에 걸려 있다고 본 것이 과했다. 임원은 리더로서 팀 운영 규칙·담당자·점검 주기·기본 모델 권장을 시스템 권한 없이 바로 정할 수 있다. 이 분리로 **회신 대기 중에도 덱이 완결된 형태가 되어 8/29 일정 리스크가 줄었다**
  **결과**: ADR-002의 구조 노출 범위가 좁아졌다. 원칙 슬라이드 3장의 우측단이 빈 컨테이너에서 실제 내용으로 채워졌고, 부수적으로 회의 요청 사항(고성능·경량 구분 멀티에이전트 활용법을 **사례로** 제시)이 원칙 ③ 역할 분담 표로 충족됐다
  **출처**: 2026-08-13 사용자 지시 + ralplan 설계 결정 보정

- **결정**: 커리큘럼의 배수·수치는 공개 자료 기준 상대값으로 쓰고 `(고객 확인 필요)` 표시
  **왜**: 사내 Tier별 크레딧 수치와 환산 비율표를 확보하지 못했고, 추정치를 사실처럼 쓸 수 없음
  **출처**: 리서치_토큰최적화_근거.md §2

## 막힌 것 / 대기 중

- **Tier 1~4별 월간 크레딧 수치와 임원 티어 분포** — 오정아 프로가 확인 예정 (회의록 Action Item). 확보 전까지 티어별 가이드가 자리표시 상태
- **크레딧-토큰 환산 비율표 (모델별·이용 방식별)** — 사내 정책 문서 필요. 커리큘럼의 핵심 비교표 수치가 여기 걸려 있음
- **엔터프라이즈 도입 서비스 구성** — 어떤 제품을 어떤 방식으로 쓰는지에 따라 화면 캡처와 사례가 달라짐
- **임원의 조직 단위 사용 현황 열람 권한** — 없으면 원칙 ① 조직 차원을 "확인 요청" 수준으로 낮춰야 함
- **오정아 프로 이메일 주소** — 전달 예정 상태
- **강사** — 강의력 검증 조건, 초안 확정 후 섭외
