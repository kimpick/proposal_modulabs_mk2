01
문제 정의

AI를 쓸수록 커지는 토큰 부담

AI 도구를 본격적으로 도입한 기업에서는 토큰 소모 관리가 공통 과제가 되었습니다. 쓰는 일이 늘수록 소모는 예상보다 빠르게 늘고, 정작 중요한 일에 충분히 쓰기 어려워집니다.

1
쓰는 방식이 바뀌었습니다
답변만 하던 도구가 스스로 자료를 찾고 여러 단계를 처리합니다. 같은 일을 맡겨도 오가는 분량이 크게 늘었습니다.
2
얼마를 쓰는지 보이지 않습니다
어느 작업이 얼마를 쓰는지 화면에 드러나지 않아, 다 쓰고 나서야 알게 됩니다. 계획도 통제도 어렵습니다.

현장에서 반복되는 이야기

  • 어제 하던 작업을 이어가려고 배경과 자료를 처음부터 다시 넣습니다.
  • 대화가 길어질수록 차감은 빠르게 늘어납니다.
  • 팀마다 쓰는 방식이 달라 누가 얼마나 쓰는지 파악하기 어렵습니다.
  • 결국 크레딧은 많이 써서 바닥나는 것이 아니라, 같은 내용을 여러 번 다시 계산하면서 바닥납니다.
사내 크레딧 제도에서는 이 문제가 월말 소진으로 드러납니다. 티어에 따라 월간 크레딧이 차등 부여되고 매월 1일 리셋되기 때문입니다. 이 30분에서 정리하는 3원칙은 이어지는 워크샵 순서에도 그대로 적용됩니다.

원리

토큰이 깎이는 원리 — 앞 내용을 매번 다시 계산

토큰은 사용량을 세는 단위이며, 질문과 답변 양쪽이 모두 차감 대상입니다. 답변 분량을 미리 지정하면 생성 분량과 되묻는 왕복이 줄어 그만큼 차감이 줄어듭니다.

각 회차까지의 누적 입력량. 진한 칸은 그 회차의 신규 입력분입니다.

열 번째 질문을 할 때 도구는 앞의 아홉 개 대화를 처음부터 다시 계산합니다. 이어 쓰면 소모가 길이에 비례해 늘지 않고 그보다 빠르게 늘어납니다.

05
원칙 ②

절감 — 같은 일을 짧게 끝낸다

차감이 일어나는 지점은 네 곳입니다. 지점마다 줄이는 방법이 다릅니다. 어디를 줄이는지 알고 쓰면 결과 품질을 낮추지 않고도 차감만 줄일 수 있습니다.

줄이는 지점구체적인 방법
입력

조직 차원 — 리더가 정할 것

  • 사내 공용 기본자료를 만든다. 용어집 · 보고 양식 · 업무 지침. 담당자와 기한을 지정하는 것이 리더의 몫입니다.
  • 문서를 통째로 돌리지 않고 요약본을 공유하는 것을 팀 규칙으로 둡니다.
공용 자료가 없으면 각자 매번 같은 배경을 붙여넣게 되고, 조직 전체로 보면 같은 내용을 인원수만큼 반복해서 지불하는 셈이 됩니다.
06
원칙 ③

재사용 — 한 번 만들어 계속 쓴다

반복하는 업무는 지시문으로 만들어 스킬처럼 등록해 둡니다. 역할과 규칙, 산출물 서식을 한 묶음으로 저장해 이름만 불러 쓰는 방식입니다(도구마다 명칭은 다릅니다). 고정된 배경 정보도 한 번 등록해 두면 입력 분량과 왕복이 함께 줄어듭니다.

한 번 등록하는 것과 매번 넣는 것

층담기는 것주기
시스템 지시문역할, 지켜야 할 규칙, 하지 말 것 (예: 보고 대상과 톤, 인용 규칙, 추측 금지)한 번 등록
업무 서식산출물 형식과 좋은 예시한 번 등록
이번 요청이번 자료와 이번 지시만매번
매번 넣는 것이 마지막 한 층뿐이라 입력 분량이 줄고, 형식을 다시 설명하는 왕복도 사라집니다.

조직 차원 — 리더가 정할 것: 팀 에이전트 세팅

  • 업무별로 담당 에이전트를 지정합니다. 지시문 + 모델 등급 + 참고 자료를 한 묶음으로 묶어 팀 공용으로 둡니다.
  • 예: 보고서 초안 · 회의록 정리 · 자료 조사 · 코드 검토
  • 잘 만든 지시문 하나가 조직 전체의 소모를 줄입니다.
  • 조직 기본 모델은 표준 등급으로 권장합니다.
작업 성격별로 쓸 모델과 방식을 미리 정해두면 매번 다시 판단하지 않아도 됩니다. 같은 모델 안에서의 절감은 그대로 성립하며, 도구 내부의 추가 절감이 적용되는지는 사내 서비스 구성에 따라 다릅니다.
06
원칙 ③

시연 — 지시문을 등록하면 무엇이 달라지나

같은 요청을 등록 전과 등록 후로 처리했을 때, 매번 넣는 분량이 어떻게 달라지는지 비교합니다.

등록 전 — 매번 넣는 네 덩이

  • 역할 설명 — “너는 우리 팀 보고서를 쓰는…”
  • 지켜야 할 규칙
  • 보고서 형식과 예시
  • 이번 자료와 요청

등록 후 — 한 번 등록 + 매번 한 덩이

한 번 등록해 둔 것
역할 · 규칙 · 형식과 예시
매번 넣는 것
이번 자료와 요청뿐
매번 넣던 세 덩이가 사라집니다.
형식을 다시 설명하느라 생기던 되묻는 왕복도 함께 줄어듭니다.
06
원칙 ③

내 업무 매트릭스 — 어디를 먼저 바꿀 것인가

업무를 이렇게 늘어놓고 보면 어디를 먼저 손볼지가 드러납니다. 임원 업무를 예로 채워 봤습니다.

업무AI 활용도소모 강도권장 모델과 방식
주간 · 월간 보고 초안높음중간표준 모델 + 등록한 지시문
회의록 정리 · 요약높음낮음경량 모델
시장 · 경쟁사 자료 조사중간높음고성능 모델, 목적이 분명할 때만
의사결정 검토 · 리스크 점검중간높음고성능 모델
형식 변환 · 번역높음낮음경량 모델

진단 기준

  • 활용도 높고 소모 강도 높은 칸 — 여기가 우선 손볼 곳입니다. 지시문 등록과 모델 조정 효과가 가장 큽니다.

  • 활용도 낮고 소모 강도 높은 칸 — 정말 필요한 작업인지 먼저 확인합니다.
