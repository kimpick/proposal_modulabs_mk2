## 1. 주장 ↔ 근거 대조

| # | 커리큘럼 주장 | 위치 | 근거 |
|---|---|---|---|
| 1 | 체감 2~4배 증가의 원인은 도구가 여러 단계를 스스로 처리하는 방식으로 전환된 것. 작업당 **5~30배** 토큰 소모 | §3 원리 4) | Gartner 2026-03 분석. 에이전트는 표준 챗봇 대비 작업당 5~30배 토큰 사용. 파일럿을 넘긴 기업들이 청구서를 받고서야 이 배수를 인지 |
| 2 | 대화가 길어지면 **앞의 내용을 매번 다시 계산**. 20번째 단계에서 같은 이력을 20번 지불 | §3 원리 2) | 컨텍스트 누적 분석 — 소모의 3대 원인은 시스템 지시문, 도구 출력, 대화 이력. 이력은 자동으로 늘어나 10번째 턴에서 1~9턴 전체를 재전송 |
| 3 | **이용 방식별 소모 강도**: 대화창(낮음) < 코드 도구(높음) < 여러 단계 자동 처리(높음) | §3 원리 3) 표 | Claude Enterprise consumption guide — Chat(Lower) / Claude Code(Higher, 시스템 지시문·파일 컨텍스트·도구 호출·다중 턴 추론) / Cowork(Higher, 다단계 실행) |
| 4 | **모델별 소모 강도**: 경량(낮음) → 표준(보통) → 고성능(높음) → 최상위(매우 높음). 고성능은 같은 작업에 표준의 **여러 배** | §3 원리 3) 표, §3 원칙③ | 동일 문서 — Haiku(Low) / Sonnet(Moderate, 권장 기본값) / Opus(High) / Fable(Very High). "Opus consumes several times more tokens than Sonnet for the same task" |
| 5 | 앞부분이 고정되면 재계산을 건너뜀 — **41~80% 절감**, 첫 응답 **13~31% 단축** | (고객 대면물 인용 보류) | PwC 2026-01 연구. OpenAI·Anthropic·Google 3사 공통. ⚠️ **연구 조건은 API 레벨에서 개발자가 캐시 지점을 직접 배치한 경우다.** 공개 문서의 프롬프트 캐싱은 API 전용이며 채팅·엔터프라이즈 화면의 자동 캐싱은 문서화되어 있지 않다. 또 캐시 읽기는 무료가 아니고(입력 단가의 일부 과금) 유효시간과 접두 일치 조건이 붙는다 → **"등록해 두면 다시 계산하지 않아 차감이 줄어든다"는 서술의 근거로 쓸 수 없다.** 원칙 ③의 절감 근거는 "입력 분량·왕복 감소"로 대체함 |
| 6 | 압축·캐싱·작업별 모델 구분을 **조합하면 40~60% 절감** | §3 원칙③, §4 | 엔터프라이즈 LLM 비용 통제 사례 분석. 프롬프트 압축·의미 기반 캐싱·모델 라우팅 조합으로 API 지출 40~60% 절감 |
| 7 | 길어진 대화를 요약해 새로 옮기면 누적 분량을 버릴 수 있음 — 실측 **132k → 2.3k 토큰(98% 감소)** | §3 원칙② | 자동 압축(auto-compaction) 실측 사례. 요약 시 설계 결정·미해결 사항은 보존하고 중복 도구 출력을 폐기 |
| 8 | 한 작업을 여러 도구로 나눠 처리 (역할 분담) | §3 원칙③ 조직 | Anthropic, *Effective context engineering for AI agents* — 서브에이전트는 별도 컨텍스트에서 작동하고 **1,000~2,000 토큰 요약만** 반환 |
| 9 | 조직 통제 수단: 부서·개인별 소모 현황, **도달 알림**, 조직 기본 모델 지정, 모델 접근 권한 | §3 원칙① 조직 | Claude Enterprise 관리자 분석·비용 통제. 조직·그룹·개인 각 층위에 한도를 둘 수 있고, 관리자는 75·90%, 사용자는 75·95%에 알림. ⚠️ 이 임계값은 **달러 지출 한도** 기준이며 사내 크레딧 풀 적용 여부는 미확인 → 고객 대면물에서는 "4분의 3 지점과 소진 임박 지점"으로 완화 표기. 층위 간 덮어쓰기 우선순위는 원문에서 확인하지 못했으므로 주장하지 않는다 |
| 10 | 티어 배분을 실측 데이터로 재조정 가능 | §3 원칙① 조직 | 동일 — 사용자별·모델별 지출 리포트를 CSV로 내보낼 수 있음(이메일, 모델, 요청 수, 입출력 토큰, 순·총지출) |
| 11 | 한 대화에 여러 작업을 섞으면 품질도 떨어짐 | §3 원칙② | 컨텍스트 오염 — 관련 없는 작업을 섞으면 모든 작업의 품질이 함께 저하. 컨텍스트가 차면 앞선 지시를 잊기 시작 |
| 12 | 인사말·군더더기 제거, 결과 형식 먼저 지정 | §3 원칙② | 국내외 실무 가이드 다수 — 예의 표현은 모델이 무시하지만 비용은 발생 |
| 13 | 월간 크레딧을 근무일로 나눠 하루 사용 기준을 정함 | §3 원칙① | 예산 페이싱 실무 — 계층별 예산을 동시 가드레일로 설계하고, 지출 한도를 조직·부서·개인 3단으로 병렬 적용 |

> **수치 표기 원칙 (2026-08-13 확정)**: row 1(Gartner 2026-03)·row 5(PwC 2026-01)·row 6은 §3 출처 목록에 직접 링크가 없다. 고객 대면물(덱·배포물)에서는 기관명을 단정하지 않고 **"업계 조사 기준"** 으로 표기 완화한다. `커리큘럼_초안_v1.md`가 이미 같은 방식을 쓰고 있어(§3 "업계 조사에 따르면 작업당 5배에서 30배") 표기가 일관된다.
>
> **row 6 정정 이력 (2026-08-13)**: 최초 작성 시 주장 열의 상한이 근거 텍스트보다 높게 적혀 있었고, 절감 폭을 "작업별 모델 구분" 단독 효과로 귀속했다. 근거는 압축·캐싱·라우팅 **조합** 기준이며 상한도 근거 텍스트가 정본이다. 주장과 귀속을 근거대로 수정했다. 덱에서 "작업별 모델 선택"만의 단독 절감 폭으로 인용하지 않는다.
