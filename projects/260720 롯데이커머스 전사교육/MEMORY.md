## CI 이슈 (PR #55) — 진단 완료, 미해결

`.github/workflows/validate-pr.yml`의 선재 버그. **이 브랜치는 워크플로를 수정하지 않았고, `origin/main`에 동일 코드가 있다.**

| # | 문제 | 근거 | 패치 |
|---|---|---|---|
| ① | **한글 폴더명 미감지** | git 기본 `core.quotePath`가 비ASCII 경로를 `"..."`로 인용 → `grep -E '^projects/'` **0건 매칭** (quotePath=false면 5건) | `git -c core.quotePath=false diff` |
| ② | 오검출 | 2-dot diff가 main 단독 변경까지 끌어와 `NIA` 검출 | `BASE...HEAD` (3-dot) |
| ③ | `IndentationError` | `python3 -c` 인라인 코드가 YAML 블록 들여쓰기를 물고 감. YAML에선 열 0 불가 | `scripts/`로 분리 |
| ④ | **폴더 단위 검증** | `find`/`os.walk` 모두 dot 디렉터리를 안 건너뜀. 폐기·아카이브 자산까지 전부 검사 | **변경된 content.json만 검증** |

**①의 파급**: 이 저장소 고객사 폴더는 대부분 한글이므로 **CI가 한글 폴더를 한 번도 검증한 적이 없다.** 통과 표시는 "검사 대상 0건"이었다.

**④가 필요한 이유 (실측)**: 감지만 고치면 `content.json` **132건 중 58건 실패(44%)**, **고객사 91곳 중 33곳(36%)** 이 빨간불이 된다. `validate_content.py`가 **WARN 3건 이상을 `NEEDS_FIX`(exit 1)** 로 처리하기 때문이며, 대부분 `module_name` 15자 초과 경고다. 변경 파일만 검증하면 이 PR은 실패 0건으로 통과한다(실측 확인).

**권고**: ①~④를 **별도 PR**로 처리. 이 PR에 섞으면 저장소 전체 영향 변경이 제안서 내용 리뷰에 묻힌다.
