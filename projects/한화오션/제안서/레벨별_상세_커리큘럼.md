## Lv.1 · 프롬프트 엔지니어링 (4시간)

**도구**: Claude Desktop 또는 Codex Desktop (GUI 환경, 터미널 불필요)
- *Claude Desktop*: Anthropic 제공, anthropic.com/download, 로컬 파일 연동 강함 (권장)
- *Codex Desktop*: OpenAI 제공, Microsoft Store 무료 설치, OpenAI 계정 필요
**목표**: 원하는 출력을 정확하게 이끌어내는 명령 설계 역량 확보

### 핵심 개념

| 개념 | 설명 | 적용 예시 |
|------|------|-----------|
| 역할 지정 (Role) | "당신은 선박 설계 전문가입니다" | 도메인 전문 답변 |
| 구조화 출력 | XML 태그, JSON, 마크다운 테이블 | 보고서 자동 포맷팅 |
| 제약 조건 | "3줄 이내", "번호 목록으로" | 요약·정리 자동화 |
| Chain-of-Thought | "단계별로 생각해보세요" | 복잡한 기술 분석 |
| Few-shot | 예시 2~3개 제공 → 패턴 학습 | 반복 문서 작업 |

### 실습 모듈

**모듈 1-1** · 기본 프롬프트 해부 (60분)
```
실습: 동일한 질문을 아래 3가지 방식으로 입력해보기
  ① 단순 질문: "선박 용접 결함 점검 방법 알려줘"
  ② 역할+구조: "당신은 조선소 품질관리 전문가입니다. 선박 용접 결함
                 유형 5가지를 표로 정리하고 각 점검 방법을 작성하세요."
  ③ Few-shot:  예시 1개 제공 후 동일 형식으로 생성 요청

비교 포인트: 출력 길이 / 정확도 / 실무 활용 가능성
```

**모듈 1-2** · 조선·엔지니어링 업무 맞춤 프롬프트 (90분)
```
직군별 실습 시나리오 (개발자·기술직군 기준):
  - 설계직: 선도설계 검토 의견서 초안 자동 생성
  - 생산직: 공정 이상 보고서 3줄 요약 → 이메일 초안
  - 품질직: 검사 체크리스트 자동 생성 (BOM 기반)
  - IT/자동화직: 시스템 장애 로그 분석 → 원인 요약 → 조치 권고안
```

**모듈 1-3** · 프롬프트 라이브러리 구축 (90분)
```
산출물: 개인 프롬프트 라이브러리 (최소 5개)

템플릿 형식:
  [이름] 주간 업무 요약기
  [용도] 긴 업무 내용 → 3줄 요약 + 다음 주 액션
  [프롬프트] ---
  당신은 {직무} 담당자입니다. 아래 내용을 읽고:
  1. 핵심 완료 사항 3가지 (1줄씩)
  2. 이슈·리스크 (있으면)
  3. 다음 주 액션 2가지
  로 정리하세요.
  {업무 내용}
  ---
```

**레벨업 체크포인트**
- [ ] 역할+구조화 프롬프트로 실무 문서 1종 자동 생성 완료
- [ ] 나만의 프롬프트 라이브러리 5개 이상 작성
- [ ] 동료와 프롬프트 공유 및 개선 1회 이상

**도구**: Claude Desktop 또는 Codex Desktop (Lv.1에서 선택한 도구 유지) + CLI 입문
- Claude Desktop 경로: `CLAUDE.md` 기반 컨텍스트 → Claude Code CLI 전환
- Codex Desktop 경로: `AGENTS.md` 기반 컨텍스트 → Codex CLI 전환
**목표**: 대화 맥락을 설계·관리하여 일관된 AI 파트너 환경 구축

### 핵심 개념

```
컨텍스트 = AI가 "기억"하는 모든 것

┌─────────────────────────────────────────────────────────┐
│  시스템 프롬프트          ← 항구적 지시 (역할·규칙·제약)  │
│  CLAUDE.md / AGENTS.md   ← 프로젝트 지식 베이스         │
│  대화 히스토리            ← 현재 세션 맥락               │
│  파일·도구 결과           ← 외부 컨텍스트                │
└─────────────────────────────────────────────────────────┘

핵심 원칙: 컨텍스트 창은 유한하다 → 무엇을 넣을지 설계가 필요
```

| 개념 | 설명 | 실무 적용 |
|------|------|-----------|
| 시스템 프롬프트 | 세션 전반 동작 규칙 설정 | 팀 표준 어투·형식 고정 |
| CLAUDE.md | 프로젝트 지식 문서 | 선박 규격·용어 사전 탑재 |
| 메모리 설계 | 중요 정보 압축 보존 | 장기 프로젝트 컨텍스트 유지 |
| 컨텍스트 창 최적화 | 불필요 토큰 제거 | 비용·속도 개선 |

## Lv.3 · 하네스 엔지니어링 (8시간)

**도구**: Claude Code CLI 또는 Codex CLI (Lv.2에서 선택한 경로 유지, 터미널 전용)
- Claude Code CLI: 로컬 파일 직접 접근, MCP 연동 강함, CLAUDE.md 자동 인식
- Codex CLI: GPT-5-Codex 모델, AGENTS.md 자동 인식, MCP(STDIO) 지원
**목표**: 파일·코드·외부 도구를 AI와 연결하는 실행 환경 구축

### 핵심 개념

```
하네스(Harness) = AI가 실제로 "일을 처리할 수 있는" 환경

  파일 시스템 ──┐
  코드 실행  ──┤── Claude Code CLI ──┐
  외부 도구  ──┘  또는 Codex CLI    ├──▶ 자동화 결과물
  (MCP 등)                          │
                                    └── (둘 다 MCP 지원)
```

| 개념 | 설명 | 한화오션 적용 |
|------|------|--------------|
| 파일 읽기·쓰기 | AI가 실제 파일 조작 | 도면 메타데이터 추출, 보고서 생성 |
| 코드 생성·실행 | Python·Shell 스크립트 작성 | BOM 자동 집계, 공정 데이터 분석 |
| MCP 연동 | 외부 시스템 연결 | Notion, Git, 데이터베이스 |
| 서브에이전트 | 병렬 작업 분리 실행 | 여러 도면 동시 검토 |

### 실습 모듈

**모듈 3-1** · CLI 하네스 심화 (120분)
```
실습 A: 파일 기반 자동화 (Claude Code CLI / Codex CLI 동일 방식)
  # 현재 디렉토리의 모든 Excel 보고서를 요약
  claude "reports/ 폴더의 xlsx 파일들을 읽고 각 파일의 핵심 지표를 표로 정리해줘"
  codex  "reports/ 폴더의 xlsx 파일들을 읽고 각 파일의 핵심 지표를 표로 정리해줘"

  # 코드 생성 + 즉시 실행
  claude "Python으로 BOM CSV를 읽어서 중량 합계를 자재 카테고리별로 집계하는 스크립트 작성 후 실행해줘"
  codex  "Python으로 BOM CSV를 읽어서 중량 합계를 자재 카테고리별로 집계하는 스크립트 작성 후 실행해줘"

실습 B: 반복 업무 자동화 스크립트

  - 출력: 통합 주간 보고서 (마크다운 → PDF)
```

**목표**: 에이전트가 스스로 발견·실행·검증·반복하는 루프를 설계하는 엔지니어 되기

### 핵심 개념: 루프의 6가지 빌딩블록

```
루프(Loop) = 내가 프롬프트하는 게 아니라, 시스템이 프롬프트하는 구조

  ┌─────────────────────────────────────────────────────────────┐
  │  ① Automations  ─── 스케줄 기반 자동 발견·분류             │
  │  ② Worktrees    ─── 에이전트 간 파일 충돌 방지 (격리)      │
  │  ③ Skills       ─── 프로젝트 지식 외부화 (SKILL.md)        │
  │  ④ Connectors   ─── MCP로 기존 도구 연결 (Notion, Git 등)  │
  │  ⑤ Sub-agents   ─── 만드는 에이전트 vs 검증하는 에이전트  │
  │  ⑥ Memory       ─── 루프 간 상태 기억 (외부 파일/보드)    │
  └─────────────────────────────────────────────────────────────┘
  Lv.3 하네스 = 단일 에이전트가 환경을 갖춤
  Lv.4 루프  = 하네스 위에서 시스템이 에이전트를 호출
```

| 빌딩블록 | Claude Code | Codex | 한화오션 적용 |
|---------|-------------|-------|--------------|
| **① Automations** | `/loop`, cron, GitHub Actions hooks | Automations 탭 (스케줄 + Triage 인박스) | 매일 아침 CI 실패·지연 공정 자동 스캔 |
| **② Worktrees** | `git worktree` + `isolation: worktree` 설정 | 빌트인 Worktree 지원 | 여러 에이전트가 동일 도면 저장소 동시 작업 |
| **③ Skills** | `.claude/agents/` + SKILL.md | `.codex/agents/*.toml` + SKILL.md | 선박 규격·BOM 구조·도면번호 체계 탑재 |
| **④ Connectors** | MCP 서버 (HTTP/STDIO) | MCP 서버 (STDIO만 지원) | SAP·Notion·Git 연동 |
| **⑤ Sub-agents** | maker → checker 분리 | TOML 정의 멀티 에이전트 | 설계 에이전트 → 품질 검증 에이전트 |
| **⑥ Memory** | 외부 마크다운 상태 파일 | 외부 마크다운 상태 파일 | `loop_state.md` — 완료/진행/대기 항목 |

### 핵심 프리미티브 (양쪽 도구 공통)

```
/loop  — 지정 주기로 프롬프트 반복 실행 (cadence 기반)
/goal  — 검증 조건이 참이 될 때까지 실행 지속
         (작성한 에이전트가 아닌 별도 소형 모델이 완료 여부 판정)

예시:
  claude /goal "quality_logs/의 모든 NG 항목이 처리되고
                reports/today_summary.md가 생성된 상태"
  codex  /goal "quality_logs/의 모든 NG 항목이 처리되고
                reports/today_summary.md가 생성된 상태"
```

### 실습 모듈

**모듈 4-1** · Worktrees + Tmux 병렬 환경 구성 (120분)
```
핵심 원리: 두 에이전트가 같은 파일을 동시에 수정하면 충돌 발생
           → 각 에이전트를 독립 워크트리에서 실행

실습 A: Git Worktree 기반 격리
  # 에이전트별 독립 작업 디렉토리 생성
  git worktree add ../agent-design  feature/design-review
  git worktree add ../agent-quality  feature/quality-check

  # 각 워크트리에서 에이전트 실행
  cd ../agent-design  && claude "선도설계 도면 리뷰 초안 작성"
  cd ../agent-quality && claude "동일 도면의 품질 체크리스트 검증"

실습 B: Tmux로 병렬 실행 시각화
  tmux new-session -s hanwha-loop

  [창 1] agent-design  워크트리 — 설계 에이전트
  [창 2] agent-quality 워크트리 — 검증 에이전트
  [창 3] loop_state.md 실시간 모니터링 (watch cat loop_state.md)
  [창 4] 결과 병합 / 로그

체감 포인트: 충돌 없이 병렬 작업 → 단일 실행 대비 시간 비교
```

**모듈 4-2** · Automations + /goal 루프 설계 (120분)
```
빌딩블록 ①⑥ 실습: 스케줄 자동화 + 상태 파일

Step 1: 상태 파일(Memory) 설계
  loop_state.md 형식:
  ## 오늘 날짜: 2026-XX-XX
  ### 처리 완료
  - [x] NG-001: 용접부 균열 → 원인: 재료 불량 → 조치 완료
  ### 진행 중
  - [ ] NG-002: 도장 박리 → 분석 중
  ### 대기
  - [ ] NG-003: 치수 초과 → 미할당

Step 2: /goal 루프 실습
  # ⚠️ 격리된 테스트 환경에서만 실행 (IT 보안팀 사전 승인)
  claude /goal "loop_state.md의 모든 '대기' 항목이 '처리 완료'로 전환된 상태"

  → 에이전트가 스스로 NG 항목 분석 → 조치 초안 작성 → 상태 업데이트 반복
  → 조건 달성 시 자동 종료 (별도 검증 에이전트가 완료 판정)

Step 3: Automation 스케줄 등록
  Claude Code: cron 또는 /loop 10m "loop_state.md 확인 후 새 NG 항목 처리"
  Codex:       Automations 탭 → 주기 설정 → Triage 인박스 연동
```

### 루프 엔지니어링 3가지 경고

> 루프가 작동한다고 해서 루프가 옳다는 뜻이 아닙니다.

```
① 검증은 여전히 인간의 몫 (Verification is on you)
   루프가 무인으로 실행될수록, 루프가 실수도 무인으로 반복한다.
   Checker 서브에이전트는 도구이지 보증이 아님.

② 이해 부채 (Comprehension Debt)
   루프가 빠를수록, 내가 이해하지 못한 코드/문서가 쌓이는 속도도 빨라진다.
   루프가 만든 것을 읽지 않으면 루프는 기술 부채 가속기가 된다.

③ 인지 항복 (Cognitive Surrender)
   루프가 편할수록, 결과를 그냥 받아들이고 싶은 유혹이 커진다.
   루프를 설계하는 것과 루프에 생각을 위탁하는 것은 같은 행동처럼 보이지만 반대 결과를 낳는다.
```
