## 1. 게이미피케이션 설계 철학

### 1.1 왜 게이미피케이션인가

| 문제 | 기존 교육 방식 | 게이미피케이션 방식 |
|------|---------------|-------------------|
| AI에 대한 거부감 | "또 교육이야" | "이번엔 뭐 하지? 재밌겠는데" |
| 수동적 태도 | 듣기만 하고 끝 | 직접 릴레이·배틀하며 능동적 참여 |
| 실무 연결 부족 | 이론 위주 | 실제 본인 업무 파일로 PoC |
| 일회성 효과 | 교육 후 잊힘 | L-Zero 서약으로 행동 변화 연결 |

### 1.2 핵심 설계 원칙: RAMP 프레임워크

- **R**elatedness: 조별 프롬프트 릴레이·배틀로 팀 협력 유도 (소속감)
- **A**utonomy: 개인이 직접 발굴하는 레거시 업무와 M365 앱 선택 (자율성)
- **M**astery: 타임 배틀 시각화로 성취감·숙련도 확인 (숙련도)
- **P**urpose: L-Zero 서약으로 개인 변화에 의미 부여 (목적성)

```

조별로 제공된 M365 Excel 링크에 접속해,
1번 분부터 돌아가며 AI에게 내릴 '지시 조건'을
릴레이로 덧붙여 고도화해 보겠습니다."
```

```
[프롬프트 릴레이 순서 — 조별 M365 Excel 공동 편집] (15분)
```

### 5.3 FT 퍼실리테이팅 핵심 팁

```
🎯 FT 퍼실리테이팅 10계명

1. 에너지가 전부다 — FT의 열정이 참가자의 몰입도를 결정한다
2. "정답"이 없다 — 참가자의 프롬프트를 존중하라
3. 시간을 보여줘라 — 타이머가 긴장감과 몰입을 만든다
4. 침묵을 두려워 말라 — 3초만 기다리면 누군가 말한다
5. 디브리핑이 핵심이다 — 체험보다 "해석"이 더 중요하다
6. "일단 한 번 해보세요" — 저항하는 참가자를 위한 마법의 문장
7. 동료 효과를 활용하라 — 옆 사람 결과 보여주기
8. 기술 이슈도 콘텐츠다 — "이것도 AI의 현실"로 자연스럽게 전환
9. PoC 순간을 놓치지 말라 — "진짜 내 업무가 되네?" 반응이 나왔을 때 강조
10. L-Zero 선서식은 감동으로 — 분위기 연출이 서약의 진지함을 만든다
```
