## 2. Claude Code (근거 확보도: 높음 — 공식 문서 직접 확인)

### 2.1 크레딧·한도 구조

- Team/Enterprise 플랜: 각 구성원의 사용량이 **좌석 할당량(seat allowance)**에서 차감
- 리셋 주기: **롤링 5시간 창 + 주간 창** (Claude 채팅·Cowork와 공유)
- 좌석 티어: Standard / Premium 2단계
- 할당량 초과 시 usage credits를 켜야 계속 사용 가능. 조직·그룹·개인 단위 지출 한도 설정 가능

### 2.2 소모 확인

`/usage`가 제공하는 것:
- 세션 블록: 모델별 입력·출력·캐시읽기·캐시쓰기 토큰
- **플랜 사용량 분해**: 최근 사용량을 **스킬·서브에이전트·플러그인·개별 MCP 서버별 비중**으로 귀속
- **행동 플래그**: 긴 컨텍스트·캐시 미스 등이 **최근 사용량의 10% 이상**을 차지하면 경고 표시
- `d`/`w`로 24시간/7일 전환
- ※ 로컬 세션 이력 기반 → **타 기기·claude.ai 사용량 미포함**

`/insights` — 최근 세션(1회 최대 200개)을 분석해 HTML 리포트 생성. `~/.claude/usage-data/report.html`

### 2.3 절감 조치 (공식 권고 요약)

| 조치 | 명령·설정 |
|---|---|
| 작업 전환 시 초기화 | `/clear` (`/rename` 후 `/resume`로 복귀 가능) |
| 압축 지시 동봉 | `/compact 코드 변경과 API 사용법 중심으로` |
| 압축 기본 지시 고정 | `CLAUDE.md`에 `# Compact instructions` 섹션 |
| 모델 하향 | `/model` — 대부분의 코딩은 Sonnet으로 충분, Opus는 복잡한 아키텍처 결정에 한정 |
| 서브에이전트 모델 지정 | 서브에이전트 설정에 `model: haiku` |
| 도구 오버헤드 축소 | `/context`로 점유 확인 → `/mcp`로 미사용 서버 비활성화. **CLI 도구(`gh`, `aws`, `gcloud`)가 MCP보다 컨텍스트 효율적** |
| 지침 → 스킬 이전 | `CLAUDE.md` **200줄 이하** 유지, 워크플로 지침은 Skills로 (호출 시에만 로드) |
| 사고 축소 | `/effort` 하향, `/config`에서 사고 비활성화, `MAX_THINKING_TOKENS=8000` |
| 장황한 작업 위임 | 테스트 실행·문서 조회·로그 처리를 서브에이전트로 (원문은 격리, 요약만 반환) |
| 전처리 훅 | `PreToolUse` 훅으로 테스트 출력 필터링 (1만 줄 로그 → 수백 토큰) |
| 캐시 수명 유지 | `ENABLE_PROMPT_CACHING_1H=1` (크레딧 사용 중에도 1시간 유지) |
| 재작업 예방 | Plan mode(Shift+Tab) → 승인 후 실행 · Esc로 조기 중단 · `/rewind`로 체크포인트 복원 |

### 2.4 참고 비용 기준선 (공식)

- 개발자 1인당 **활동일 기준 약 $13**, **월 $150~250**
- 사용자 90%는 활동일당 $30 미만
- 백그라운드 소모: 세션당 통상 $0.04 미만
- **에이전트 팀은 표준 세션 대비 약 7배** 토큰

## 3. Gemini CLI (근거 확보도: 중 — 문서·커뮤니티 자료 기반)

| 명령 | 기능 |
|---|---|
| `/compress` | 시스템 컨텍스트를 제외한 전체 대화를 요약으로 치환 |
| `/chat save` / `/chat resume` | 대화 상태를 브랜치처럼 저장·복원 (현재 컨텍스트를 통째로 교체) |
| `/stats` | 세션 토큰 사용량, 캐시 절감분, 세션 시간. 서브커맨드로 세션별·모델별(쿼터 포함)·도구별 통계 |

**압축 임계 설정** — 모델 총 토큰 한도의 비율(0~1)로 지정. 예: `0.6` → 히스토리가 한도의 60%를 넘으면 압축 트리거.

**컨텍스트 파일** — `GEMINI.md` (계층적 로드)

출처: https://google-gemini.github.io/gemini-cli/docs/cli/commands.html · https://google-gemini.github.io/gemini-cli/docs/get-started/configuration.html · https://deepwiki.com/google-gemini/gemini-cli/4.12-chat-compression-and-context-management

## 4. GitHub Copilot (근거 확보도: 중~높음 — 공식 문서 + 업계 분석)

### ⚠️ 구조 일치 주목

**2026-06-01부터 모든 Copilot 플랜이 사용량 기반 과금으로 전환**되며, premium request 카운트 대신 **월 단위 GitHub AI Credits 할당**으로 바뀌었습니다. 소비량은 **입력·출력·캐시 토큰**을 합산해 계산됩니다.

이 구조가 고객이 설명한 조건과 상당 부분 일치합니다:

| 고객 진술 | Copilot AI Credits | Claude Enterprise |
|---|---|---|
| "월 단위로 일정량의 Credit이 부여" | ✅ 월 할당 | ❌ 롤링 5시간 + 주간 창 |
| "매월 1일 리셋" | ✅ 월 주기 | ❌ 주 단위 |
| "모델마다 Token 대응 비율이 다름" | ✅ **모델 배수(multiplier)** | ⚠️ 모델별 단가 차이는 있으나 "배수" 개념은 아님 |
| "서비스 방식마다 다름" | ✅ 기능별 배수 (코드 리뷰 13×) | — |
| "Tier1~4 차등" | ⚠️ 플랜별 할당은 있으나 4단 티어는 사내 커스텀 가능성 | ⚠️ Standard/Premium 2단 |

> **이것은 가설이지 결론이 아닙니다.** 사내 게이트웨이가 임의의 티어 체계를 씌운 경우도 동일한 진술이 나옵니다. 다만 **"매월 1일 리셋 + 모델별 배수"** 조합은 Copilot AI Credits 구조와 가장 잘 맞으므로, 고객 확인 시 이 방향을 먼저 물어볼 근거가 됩니다.

### 4.1 모델 배수 (확인된 사례)

| 대상 | 배수 |
|---|---|
| GPT-5 mini 등 포함 모델 | **0×** |
| 표준 모델 | 1× |
| 고급 추론 모델 | **5× ~ 20×** |
| Copilot 코드 리뷰 (PR당) | **13×** |
| 자동 모델 선택 (유료 플랜 대상 모델) | **10% 할인** |

### 4.2 절감 조치

- **0× 모델로 라우팅** — 상담·확인성 질의를 포함 모델로 돌리면 소비가 급감 (§5차원 3. 하네스의 가장 직접적 구현)
- **자동 모델 선택 활용** — 대상 모델에 10% 배수 할인
- **비채팅 프리미엄 사용 차단** — `GitHub > Copilot > Editor`에서 *Enhance non-chat requests with premium models* 끄기
- **관리자 가시성** — 사용량 대시보드 · Copilot Metrics API (2026-06-19부터 `ai_credits_used` 필드 제공, 단 **모델·기능·표면별 분해는 아직 미지원**) · Billing Usage API

## 5. 루프 차원 주의 — 통제 지점이 제품 밖에 있다

5차원 중 **4. 루프**만 벤더 대응표가 거의 비어 있습니다. 이는 자료를 못 찾아서가 아니라 **구조적인 사실**입니다.

- 반복 상한, 재시도 예산, 무진전 감지, 2-strike 룰 같은 통제는 **대화형 제품(웹 채팅·IDE·CLI)의 설정 항목이 아닙니다.** 이들은 에이전트를 돌리는 **자동화·프레임워크 층**에 존재합니다.
- 근거로 확인된 관행값: 반복 상한 기본값 **25**, 도구+인자 해시 기반 무진전 감지, 2회 실패 시 중단 — 모두 오케스트레이션 프레임워크 수준의 설정입니다.
- 제품 층에서 가능한 부분적 대응은 **조기 중단(Esc)**, **에이전트 팀원 명시 종료**, **비프리미엄 강제** 정도입니다.

### 교육 설계 함의

| 대상 | 루프 차원을 어떻게 다룰 것인가 |
|---|---|
| **임원 (30분)** | 개인 조작법이 아니라 **조직 결정 사항**으로 제시 — "자동화 도입 승인 시 종료조건·예산 상한을 필수 기재 항목으로" |
| **실무자 (본과정 M4)** | 자동화를 직접 구성하는 수강생에게는 프레임워크 층 실습. 그렇지 않은 수강생에게는 **"내가 돌리는 자동화에 상한이 걸려 있는지 확인하는 법"**으로 축소 |

> 확인 문항 3번(임원이 쓰는 표면)이 "웹 채팅"으로 나오면, 루프 차원은 **개인 레버가 아예 없습니다**. 이 경우 30분 세미나 B-4는 조직 레버 구간(C)으로 옮기는 것이 정확합니다.

## 6. 교육 투입 가이드

1. **제품 확정 전** — 본과정·세미나 모두 리서치 본문의 **중립 원리**로만 진행. 이 부록은 강사 참고용으로만 배포.
2. **제품 확정 후** — 해당 열을 뽑아 **실습 시트 1장**으로 만들어 배포 자료에 포함. 상담에서 요청된 *"추후 직접 시도해볼 수 있는 가이드"*가 정확히 이것입니다.
3. **멀티 제품 환경이면** — 열을 나란히 두고 **"같은 원리, 다른 명령"** 구성으로 제시. 원리를 배운 사람은 제품이 바뀌어도 이전 가능하다는 메시지가 임원에게 유효합니다.
