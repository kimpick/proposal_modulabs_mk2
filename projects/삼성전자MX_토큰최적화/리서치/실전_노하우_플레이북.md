## 0. 오늘 당장 바꾸는 10가지 (요약 카드)

| # | 기술 | 표면 | 한 줄 |
|---|---|---|---|
| 1 | **잘못 나오면 다시 묻지 말고 원래 질문을 고쳐라** | 💬 | 재질문은 대화를 늘리고, 수정은 늘리지 않는다 |
| 2 | 작업이 바뀌면 **새 대화**를 연다 | 💬 | 초기화는 공짜, 압축은 유료 |
| 3 | 질문 5개는 **한 메시지에 묶어서** | 💬 | 긴 문서를 5번 다시 읽히지 않는다 |
| 4 | 출력에 **분량·형식 상한**을 항상 건다 | 💬 | 출력은 입력의 5~10배 단가 |
| 5 | **"모르면 추측 말고 먼저 물어라"** 한 줄 추가 | 💬 | 빗나간 장문 한 번이 질문 한 번보다 비싸다 |
| 6 | 긴 문서는 **요약본을 만들어 그걸 붙인다** | 💬 | 원본은 한 번만 처리 |
| 7 | 잔일은 **경량 모델**로 (요약·번역·형식변환·분류) | 💬 | 환산율이 낮은 경로로 이동 |
| 8 | 모델·추론강도는 **세션 시작 때 정하고 중간에 안 바꾼다** | ⌨️ | 중간 변경 = 전체 재처리 |
| 9 | 버릴 경로는 `/compact` 말고 **`/rewind`** | ⌨️ | rewind는 캐시된 지점으로, compact는 새로 만든다 |
| 10 | 안 쓰는 **도구·커넥터는 꺼둔다** | ⌨️🏢 | 정의가 매 턴 실린다 |
| 11 | 곁가지 질문은 **`/btw`**로 | ⌨️ | 답변이 대화 기록에 안 남는다 |
| 12 | **같은 걸 두 번 교정했으면 새 세션** | 💬 | 컨텍스트가 실패한 시도로 오염된 상태 |

> **왜 줄여도 되는가** — 줄이면 품질이 떨어지는 게 아니라 **올라갑니다**. 2026년 8월 기준, 최신 모델은 '긴 문서에서 사실 하나 찾기'는 **96~99%**로 거의 완벽하지만, **여러 근거를 모아 종합하는 실제 업무**에서는 **74~89%**로 떨어집니다. 벤치마크 기준 실효 컨텍스트는 광고 창의 **50~65%** — 100만이라 쓰여 있어도 실제로는 50~65만입니다. 크레딧 절감과 정답률 향상은 같은 방향입니다. → [컨텍스트_품질_프레임.md](컨텍스트_품질_프레임.md)
> ⚠️ 이 논점의 원 연구(Chroma "Context Rot")는 **2025-07** 발표·이전 세대 모델 대상입니다. *"단순 검색조차 틀린다"* 는 지금 인용하면 안 됩니다.

## 1. 프롬프트 — 재작업을 없애는 조작법

### 1-1. 3요소 템플릿 💬

가장 큰 낭비는 재작업입니다(전체 토큰의 약 59%). 아래 3줄이 재작업을 막습니다.

```
[목적] 무엇을 위해 필요한지 한 줄
[완료조건] 무엇이 충족되면 끝인지 (검증 가능하게)
[출력형식] 어떤 모양으로, 얼마나

예)
[목적] 팀장 보고용 주간 요약
[완료조건] 지연 이슈 3건이 각각 원인·조치·기한을 포함할 것
[출력형식] 표 1개, 8행 이내, 서론·결론 없이 표만
```

**왜 줄어드는가** — 왕복 1회를 줄이면 그 시점까지의 대화 전체를 한 번 덜 보냅니다. 프롬프트를 3줄 늘리는 비용은 왕복 1회 비용의 수십 분의 1입니다.

### 1-2. "짧게" 대신 숫자로 💬

| ❌ 이렇게 쓰면 | ✅ 이렇게 |
|---|---|
| "간단히 알려줘" | "3문장 이내" |
| "표로 정리해줘" | "표만. 표 앞뒤 설명 없이" |
| "코드 짜줘" | "코드만. 주석 없이. 설명 필요하면 코드 뒤에 3줄 이내" |
| "정리해줘" | "불릿 5개 이내, 각 20자 이내" |

**왜 줄어드는가** — 출력 토큰은 입력의 5~10배 단가이고 **캐시 할인 대상이 아닙니다**. 유일한 통제 수단이 지시입니다.

### 1-3. 추측 금지 한 줄 💬

```
불확실하거나 정보가 부족하면 추측해서 진행하지 말고, 먼저 질문하라.
```

**왜 줄어드는가** — AI가 잘못 짐작하고 장문을 생성하면 그 출력 전량 + 재작업 왕복이 청구됩니다. 질문 한 줄이 훨씬 쌉니다.

### 1-4. 한 메시지에 한 작업 💬

여러 작업을 한 요청에 섞으면, 그중 하나만 틀려도 **전체를 다시 생성**하게 됩니다.

- ✅ 독립된 질문 여러 개 → 한 메시지에 묶기 (문서를 여러 번 안 읽힘)
- ❌ 연결된 작업 여러 단계 → 한 메시지에 몰기 (재작업 시 전부 날아감)

### 1-5. 설명 10줄보다 예시 1개 💬

원하는 결과물의 **샘플 하나**를 붙이는 것이 형식을 말로 설명하는 것보다 짧고 정확합니다.

### 1-6. 추론 강도 낮추기 ⌨️

확장 사고(extended thinking)는 **출력 토큰으로 과금**되며 요청당 수만 토큰에 이를 수 있습니다.

- 번역·요약·형식변환·분류 → 사고 끄거나 최저
- 설계·디버깅·다단 추론 → 유지

`/effort` 또는 `MAX_THINKING_TOKENS=8000`
⚠️ **단, 세션 중간에 바꾸면 캐시가 전부 깨집니다** (§2-8 참조). 시작할 때 정하십시오.

### 1-7. 방향이 틀렸으면 즉시 끊기 💬⌨️

끝까지 두고 보면 그 출력 전량이 과금됩니다. `Esc` 한 번이 가장 확실한 절감입니다.

## 2. 컨텍스트·세션 — 여기가 최대 절감 구간

> 매 요청은 **그때까지의 대화 전체**를 다시 보냅니다. 그래서 소모는 대화 길이에 비례가 아니라 **제곱에 가깝게** 늘어납니다. 이 절의 기술들이 그 곡선을 끊습니다.
> **동시에 품질 문제이기도 합니다** — 컨텍스트가 길어질수록 모델이 틀리기 시작합니다(Context Rot). 아래 기술들은 절감 기법이자 정확도 기법입니다.

**정리 프레임 — Write / Select / Compress / Isolate**

| 레버 | 무엇 | 이 절의 대응 |
|---|---|---|
| **Write** | 컨텍스트 밖에 기록하고 필요할 때 부른다 | 2-3 요약본 · 2-4 결정 기록 |
| **Select** | 이 작업에 필요한 것만 넣는다 | 2-7 온디맨드 지침 · §3-2 도구 끄기 |
| **Compress** | 이미 들어온 것을 압축한다 | 2-5 `/compact` · §3-5 출력 거르기 |
| **Isolate** | 작업을 분리해 서로 오염되지 않게 한다 | 2-1 편집 · 2-2 새 대화 · **2-12 `/btw`** · §3-3 서브에이전트 |

### 2-1. ★ 재질문 대신 원래 메시지를 수정 💬

**웹 채팅 사용자에게 가장 효과가 큰 단 하나의 기술입니다.**

| 방식 | 무슨 일이 일어나는가 |
|---|---|
| ❌ "아니 그게 아니고 이렇게 해줘"라고 **새로 보냄** | 빗나간 답 + 내 지적 + 새 답이 **전부 대화에 남아** 이후 매 턴 재전송 |
| ✅ 원래 메시지의 **편집(연필) 버튼**으로 고쳐서 재생성 | 빗나간 답이 **대화에서 사라짐**. 이후 턴이 그걸 안 실어 나름 |

빗나간 답변 3번이면 그 3개가 남은 대화 내내 따라다닙니다. 편집은 그걸 지웁니다.

### 2-2. 새 대화를 여는 기준 💬

**"주제가 바뀌면"이 아니라 "작업 덩어리가 끝나면"**입니다.

```
✅ 새로 연다 — 로그인 기능 끝 → 결제 기능 시작
✅ 새로 연다 — A보고서 완료 → B보고서 시작
❌ 유지한다 — 같은 보고서를 다듬는 중
```

**핵심 대비**: **초기화는 비용이 0, 압축(`/compact`)은 비용이 든다.** 이어갈 필요가 없으면 무조건 새 대화입니다.

**★ 오염 신호 — 같은 것을 두 번 이상 교정했다면 새 세션**

같은 이슈로 두 번 넘게 고쳐 말하고 있다면, 그건 지시가 부족한 게 아니라 **컨텍스트가 실패한 시도들로 오염된 상태**입니다. 실패한 시도가 컨텍스트에 남아 있으면 그것이 그대로 **방해자(distractor)**로 작동해 다음 답도 같은 방향으로 끌고 갑니다. 세 번째 교정보다 새 세션이 쌉니다.

```
새 세션에 이렇게 시작:
"[목적] ... [완료조건] ... [출력형식] ...
 참고: 이전에 A방식을 시도했다가 B 문제로 실패했으니 그 방향은 제외."
```

### 2-3. 긴 문서는 "한 번만" 읽힌다 💬

| ❌ | ✅ |
|---|---|
| 200쪽 PDF를 붙이고 질문할 때마다 다시 붙임 | 첫 세션에서 **요약본(마크다운) 1장**을 만들게 하고, 이후엔 그 요약본만 붙임 |
| 파일 첨부 후 5개 질문을 5번에 나눠 던짐 | 5개 질문을 **한 메시지에** 담아 한 번에 |

**왜 줄어드는가** — 첨부 문서는 이후 매 턴 컨텍스트에 남습니다. 요약본으로 바꾸면 그 상시 비용이 1/10 이하로 내려갑니다.

### 2-4. 세션 종료 전 "결정 기록" 습관 💬⌨️

작업을 끝내기 전에 한 번:

```
지금까지 확정된 결정사항과 다음에 할 일을 10줄 이내로 정리해줘.
```

이걸 메모/파일로 남기면, 다음 세션은 **긴 대화를 이어받지 않고 10줄로 시작**합니다. 긴 대화를 다음 날 이어가는 것이 가장 비싼 습관입니다.

### 2-5. `/compact` 제대로 쓰기 ⌨️

- **보존 지시를 반드시 동봉**: `/compact 코드 변경과 테스트 결과만 남겨줘` / `/compact 이 API 변경사항 위주로`
  → 자동 압축은 무엇이 중요한지 **추측**합니다. 지시하면 내가 고릅니다
- **타이밍**: 자동 압축(포화 직전)을 기다리지 말고 **작업 사이 자연스러운 구간**에서 수동 실행
- **임계 자체를 앞당기기**: `/autocompact 500k` — 자동 압축이 얼마나 찼을 때 돌지 직접 설정
- **비용 인지**: 압축은 요약하려고 대화를 먼저 읽으므로 그 자체가 큰 요청입니다. 캐시가 살아 있을 때(작업 직후) 하면 싸고, 오래 쉰 뒤 하면 가장 비쌉니다

**★ 컴팩션에서 무엇이 살아남는가 (공식)**

압축 후에도 지시가 남아 있을 거라고 착각하면, 사라진 규칙을 모른 채 계속 쓰게 됩니다.

| 무엇 | 압축 후 |
|---|---|
| 시스템 프롬프트·출력 스타일 | 유지 (애초에 메시지 히스토리가 아님) |
| **루트 CLAUDE.md·비스코프 규칙** | ✅ 디스크에서 **재주입** |
| Auto memory | ✅ 디스크에서 재주입 |
| **`paths:` 프론트매터 규칙** | ❌ **소실** — 매칭 파일을 다시 읽을 때까지 |
| **하위 디렉터리 CLAUDE.md** | ❌ **소실** — 그 디렉터리 파일을 다시 읽을 때까지 |
| 호출된 스킬 본문 | ✅ 재주입, 단 **스킬당 5,000 / 총 25,000 토큰 상한**, 오래된 것부터 드롭 |
| 스킬 **목록** | ❌ 재주입 안 됨 — 실제로 호출한 스킬만 보존 |
| 훅 | 해당 없음 (코드로 실행) |

**여기서 나오는 실전 규칙 2개**
1. **압축을 넘겨 반드시 살아야 하는 규칙**은 `paths:` 프론트매터를 빼거나 **루트 CLAUDE.md로 옮긴다**
2. **`SKILL.md`는 중요한 지시를 맨 앞에 둔다** — 상한 초과 시 뒤가 잘리고 앞이 보존됩니다

### 2-6. ★ 버릴 경로는 `/compact`가 아니라 `/rewind` ⌨️

거의 알려지지 않았지만 공식 문서가 명시한 기술입니다.

| | 무슨 일이 일어나는가 |
|---|---|
| `/compact` | 히스토리를 요약으로 **교체** → **새 프리픽스를 만들어야 함** → 캐시 재구축 |
| `/rewind` | 이전 턴으로 **잘라냄** → 그 지점은 **이미 캐시돼 있음** → 캐시 그대로 히트 |

**판단 기준**: 잘못된 방향으로 갔던 구간을 **통째로 버리고 싶다** → `/rewind`. 내용은 살리되 압축만 필요하다 → `/compact`.

### 2-7. 지침 파일은 200줄 💬⌨️

프로젝트 지침 파일(CLAUDE.md 등)은 **세션 시작 시 컨텍스트에 올라가 무관한 작업 중에도 계속 비용을 냅니다.**

```
1. 모든 세션에 반드시 필요한가? → No면 분리
2. 특정 경로에서만 필요? → 경로 스코프 규칙으로
3. 특정 역할에만 필요? → 서브에이전트 파일로
4. 긴 절차인가? → 스킬로 (호출할 때만 로드)
```

⚠️ **`@import`로 쪼개는 것은 정리에는 좋지만 절감에는 불충분합니다.** 시작 시 함께 로드되면 줄어든 게 없습니다. **"필요한 순간에만 로드되는 구조"**로 나눠야 합니다.

### 2-8. ★ 캐시를 깨지 않는 법 ⌨️

캐시는 **요청 앞부분(프리픽스)이 지난번과 똑같은지**로 판정합니다. 앞이 바뀌면 **뒤가 전부 무효**가 됩니다.

**캐시를 깨는 행동 (하면 다음 턴이 느리고 비쌈)**

| 행동 | 비고 |
|---|---|
| **모델 전환** (`/model`) | 모델마다 캐시가 따로. 내용이 같아도 전체 재처리 |
| **추론 강도 변경** (`/effort`) | 강도별로 캐시가 따로 |
| **fast mode 켜기** | 세션 초반에 켜면 싸고, 깊어진 뒤 켜면 비쌈 |
| **MCP 서버 연결/해제** | 도구 정의가 프리픽스에 실리는 경우 |
| **도구 전체 거부 규칙 추가** | 시스템 프롬프트 층 변경 |
| **`/compact`** | 설계상 대화 층 무효화 |
| **업그레이드 후 첫 턴** | 재시작 후 1회 |
| **긴 대화를 업그레이드 후 재개** | 가장 비싼 요청이 될 수 있음 |

**캐시를 지키는 행동 (마음껏 해도 됨)**

파일 편집 · 권한 모드 전환 · 스킬/커맨드 호출 · `/recap` · **`/rewind`** · 서브에이전트 스폰

> **공식 권고 한 줄**: *"모델과 추론 강도는 세션 시작 때 정하고, `/compact`는 작업 사이 자연스러운 구간에 쓰라. 작업 중 변경이 적을수록 캐시 히트율이 높다."*

### 2-9. 캐시 수명과 휴식 ⌨️

- 캐시는 **쉬면 만료**됩니다 (구독 1시간 / 크레딧·API 5분). 만료 후 첫 요청은 **전체를 다시 처리**합니다
- 요청이 캐시에 적중할 때마다 타이머가 리셋되므로, **일하는 동안은 계속 따뜻**합니다
- **실전**: 점심·회의로 자리를 비울 거면 **비우기 전에 세션을 정리**하십시오. 돌아와 던지는 첫 질문이 오전 대화 전체를 다시 청구합니다
- 장시간 유지가 필요하면 `ENABLE_PROMPT_CACHING_1H=1`

### 2-10. 캐시 범위 — 디렉터리를 옮기지 말 것 ⌨️

캐시는 사실상 **머신 + 디렉터리 단위**입니다.

- 다른 디렉터리에서 연 세션은 서로의 캐시를 **못 씁니다** (같은 레포의 worktree도 마찬가지)
- **같은 디렉터리에서 병렬로 띄운 세션은 서로의 캐시를 읽습니다** → 병렬 작업은 같은 디렉터리에서

### 2-11. 지침 파일은 중간에 고쳐도 적용 안 된다 ⌨️

루트 지침 파일과 출력 스타일은 **세션 시작 시 한 번 읽고 메모리에 유지**됩니다.

- 중간에 고쳐도 **캐시는 안 깨지지만 적용도 안 됩니다**
- 적용되는 시점: 다음 `/clear`, `/compact`, 또는 재시작
- 모르고 "왜 안 먹지?" 하며 반복 지시하는 것이 **순수 낭비**입니다
- 지금 무엇이 로드돼 있는지 보려면 `/memory`

### 2-12. ★ 곁가지 질문은 `/btw`로 격리 ⌨️

작업 중에 튀어나오는 곁가지 질문("이 옵션이 뭐였지?", "저 파일 어디 있었지?")을 그냥 물으면 **질문과 답변이 대화에 영구히 남아** 이후 매 턴 재전송됩니다.

```
/btw 아까 그 설정 파일 경로가 어디였지?
```

- 답변이 **대화 기록에 추가되지 않습니다**
- 질문 없이 `/btw`만 치면 최근 곁가지 질문과 답을 다시 볼 수 있습니다

**왜 중요한가** — 본 작업과 무관한 문답은 토큰만 먹는 게 아니라 **Context Rot의 방해자(distractor)로 작동**해 본 작업의 정확도까지 떨어뜨립니다. 격리는 절감이자 품질 방어입니다.

## 3. 하네스 — 무엇으로 부르는가

### 3-1. 작업별 모델 배정표 💬

고객이 이미 언급한 "Claude 고성능 / Gemini 경량 구분 사용"을 실무 기준으로 구체화한 것입니다.

| 작업 | 모델 | 이유 |
|---|---|---|
| 번역, 맞춤법, 형식 변환 | **경량** | 판단 불필요 |
| 요약, 분류, 태깅 | **경량** | 패턴 작업 |
| 로그·에러 스캔, 대량 텍스트 훑기 | **경량** | 속도가 중요, 추론 불필요 |
| 회의록 정리, 표 만들기 | **경량** | 구조화 작업 |
| 설계, 아키텍처 판단 | **상위** | 다단 추론 |
| 원인 불명 디버깅 | **상위** | 가설 수립 |
| 이해관계 얽힌 의사결정 문서 | **상위** | 맥락 통합 |
| 처음 해보는 작업 | **상위** | 실패 시 재작업 비용이 더 큼 |

**판단 한 줄**: *"내가 5분 안에 검토해서 맞는지 틀린지 바로 알 수 있는 일"이면 경량 모델로 충분합니다.*

⚠️ 세션 중간에 모델을 바꾸면 캐시가 깨집니다(§2-8). **작업 시작 전에 정하십시오.** 잔일이 여러 개면 모아서 한 세션에 처리하는 것이 효율적입니다.

### 3-2. 안 쓰는 도구·커넥터 끄기 ⌨️🏢

연결된 도구의 **정의가 매 턴 컨텍스트에 실립니다.** 보고된 사례들:

| 사례 | 점유량 |
|---|---|
| 서버 5개 · 툴 58개 | 대화 시작 전 **약 55K 토큰** |
| 툴 정의만으로 | **134K 토큰** |
| 서버 3개 | 200K 창의 **143K(72%)**를 첫 메시지 전에 |

**Notion·Gmail·Drive·Slack을 다 붙여두는 환경이라면 특히 해당됩니다.**

- `/context`로 무엇이 자리를 차지하는지 확인 (색상 격자로 시각화 + 최적화 제안)
- `/mcp`로 안 쓰는 서버 비활성화
- 동등한 기능의 **CLI 도구가 있으면 그쪽이 여전히 가장 효율적** (툴 목록 자체를 안 실음)
- 최신 버전은 **툴 정의를 기본 지연 로딩**합니다 — 툴 **이름**만 올라가고 스키마는 필요할 때 로드. `ENABLE_TOOL_SEARCH=false`로 끄면 전부 선로드되니 켜두십시오
- 항상 로드할 필요 없는 스킬은 `disable-model-invocation: true` — `/이름`으로 부를 때까지 **컨텍스트에서 완전히 빠집니다**

### 3-3. 장황한 작업은 위임 ⌨️

테스트 실행 / 로그 처리 / 문서 조회처럼 **출력이 긴 작업**은 서브에이전트에 맡깁니다.

- **원문은 서브에이전트 안에 남고, 요약만 본 대화로 돌아옵니다**
- 서브에이전트에는 **작은 모델을 지정**하십시오
- 본 대화의 캐시는 영향받지 않습니다 (스폰은 캐시 안전)

**★ 판단 기준 한 줄 (Anthropic 내부 기준)**

> **"이 툴 출력이 또 필요한가, 아니면 결론만 필요한가?"**
> 결론만 필요하다 → 서브에이전트로. 원문을 계속 참조해야 한다 → 본 대화에서.

조사·탐색·대량 파일 읽기는 거의 항상 "결론만 필요"에 해당합니다.

### 3-4. 병렬 에이전트 절제 ⌨️

에이전트 팀은 표준 세션 대비 **약 7배** 토큰을 씁니다.

- 팀은 작게
- **끝나면 즉시 종료** (종료 전까지 계속 소모)
- 스폰 프롬프트는 짧게 — 팀원은 지침·도구·스킬을 자동 로드하므로 스폰 프롬프트 내용이 시작부터 가중됩니다

### 3-5. 출력을 미리 걸러서 넣기 ⌨️

1만 줄 로그를 그대로 넣지 말고 필요한 줄만 추출해 넣습니다. 훅으로 자동화하면 **수만 토큰 → 수백 토큰**이 됩니다.

## 4. 루프 — 끝나는 조건

> ⚠️ 이 차원은 **웹 채팅에는 개인 레버가 거의 없습니다.** 자동화를 직접 돌리는 경우에만 해당합니다. 웹 채팅 사용자에게는 §4-1만 유효합니다.

### 4-1. 프롬프트로 거는 상한 💬

자동화가 없어도 지시문으로 최소한의 브레이크를 걸 수 있습니다.

```
같은 방법으로 두 번 실패하면 더 시도하지 말고 멈춰서 상황을 보고하라.
접근을 바꿀 때는 무엇을 왜 바꾸는지 먼저 한 줄로 알려라.
```

### 4-2. 3중 종료조건 ⌨️🏢

자동화·에이전트를 구성한다면 세 가지를 **반드시 함께** 겁니다.

| 장치 | 설정 |
|---|---|
| 하드 반복 상한 | 작업당 최대 스텝 수 (관행 기본값 25) |
| 토큰·예산 상한 | 예산 소진 시 강제 종료 |
| 무진전 감지 | 도구+인자 조합을 해시해 최근 창에서 반복되면 종료 |

**왜** — 재시도 폭주가 나면 낭비 비율이 정상 5% 미만에서 **80%+**로 튑니다.

### 4-3. 2-strike 룰 ⌨️🏢

첫 수정 시도가 실패하면 **바로 사람에게 넘깁니다.** 세 번째 시도의 성공률은 두 번째보다 낮은데 비용은 누적됩니다.

### 4-4. 값비싼 단계 앞에 승인 게이트 ⌨️🏢

배포·대량 처리·외부 호출 앞에 사람 승인을 둡니다. 잘못된 방향으로 전체 예산을 쓰는 것을 차단합니다.

## 5. 모니터링 — 안 보면 못 줄인다

### 5-1. 확인 시점 3개 ⌨️

| 언제 | 무엇을 | 명령 |
|---|---|---|
| 작업 시작 전 | 무엇이 컨텍스트를 차지하는가 | `/context` |
| 작업 끝난 뒤 | 이번 작업이 얼마나 썼는가 | `/usage` |
| 주 1회 | 내 소모 패턴 · 무엇이 태우는가 | `/usage` 주간 보기 · `/insights` |

### 5-2. ★ 귀속 분석 — "무엇이" 태우는지 ⌨️

총량만 보면 개선할 대상을 못 찾습니다. 소모를 **스킬·서브에이전트·플러그인·도구 서버별 비중**으로 분해해서 보십시오.

**특히**: 최근 사용량의 **10% 이상을 차지하는 행동에는 자동으로 플래그**가 붙습니다 (긴 컨텍스트, 캐시 미스 등). 플래그가 곧 진단 결과입니다.
- `긴 컨텍스트` 플래그 → §2-2, §2-4를 적용
- `캐시 미스` 플래그 → §2-8, §2-9를 적용

### 5-3. 캐시 건강도 보기 ⌨️

두 숫자의 비율만 보면 됩니다.

| 지표 | 의미 |
|---|---|
| `cache_read_input_tokens` | 캐시에서 읽음 (정가의 약 10%) |
| `cache_creation_input_tokens` | 캐시에 새로 씀 |

**read ÷ creation 비율이 높을수록 건강합니다.** creation이 턴마다 계속 높으면 **프리픽스에서 뭔가 계속 바뀌고 있다**는 뜻이니 §2-8 목록을 점검하십시오.

### 5-4. 개인 번레이트 기준선 💬

```
목표 일 소모 = 내 티어 월 크레딧 ÷ 월 근무일
런웨이 = 남은 크레딧 ÷ 최근 일 평균 소모
```

**런웨이 < 남은 근무일** 이면 경고입니다. **월초에 잡으십시오** — 20일 중 12일차에 85%를 쓴 상태면 완주하려면 73.5% 감축이 필요해져 사실상 사용 중단이 됩니다.

### 5-5. 조직 층 🏢

- 표준 원격측정(OpenTelemetry) 수출 — 사용자·세션별 토큰·비용·캐시 지표를 사내 스택으로. **모든 환경에서 작동하는 유일한 방법**
- 관리자 콘솔 지출 리포트 / 분석 API — 사용자·모델별 CSV
- 임계 알림 — 고갈 **전에** 경고

## 7. 안티패턴 — 흔한 오해

| 오해 | 실제 |
|---|---|
| "프롬프트를 짧게 쓰면 절약된다" | **짧고 모호한 프롬프트가 가장 비쌉니다.** 재작업 왕복이 절약분을 압도 |
| "대화를 이어가면 맥락이 쌓여 효율적이다" | 맥락은 쌓이지만 **매 턴 전량 재전송**됩니다. 필요한 것만 남기고 새로 시작하는 게 쌉니다 |
| "파일을 나누면 토큰이 준다" | `@import`로 나눠도 **시작 시 함께 로드되면 그대로**입니다. 온디맨드 로드여야 줍니다 |
| "압축(`/compact`)이 항상 정답" | 이어갈 필요 없으면 **초기화가 공짜**이고, 버릴 구간이면 **`/rewind`가 더 쌉니다** |
| "좋은 모델 쓰면 한 번에 끝나서 결국 싸다" | 잔일에는 성립하지 않습니다. 검토로 맞고 틀림을 즉시 알 수 있는 일은 경량이 이깁니다 |
| "모델을 그때그때 바꾸면 최적" | 세션 중 전환은 **캐시를 전부 깹니다.** 시작 때 정하고 잔일은 모아서 처리 |
| "지침 파일 고쳤으니 이제 반영됐다" | 루트 지침은 **세션 시작 시 한 번** 읽습니다. 재시작 전까지 안 먹습니다 |
| "많이 쓴 사람이 문제" | 대부분은 **쓰는 방식**의 문제입니다. 같은 산출을 절반 크레딧으로 내는 것이 목표 |
| **"토큰을 아끼면 AI가 덜 알고 답한다"** | **반대입니다.** 여러 근거를 종합하는 실제 업무에서 정확도가 **74~89%**로 떨어집니다. 절감과 정확도는 같은 방향 |
| **"컨텍스트 창이 100만이니 마음껏 넣어도 된다"** | 벤치마크 기준 실효 컨텍스트는 광고 창의 **50~65%**입니다. Anthropic도 1M 모델을 **약 967K에서 자동 압축**하고, 창을 200K로 묶는 옵션을 공식 제공합니다 |
| "요즘 모델은 긴 컨텍스트 문제 해결했다던데" | **절반만 맞습니다.** 단일 사실 검색은 96~99%로 해결됐지만 **다중 종합은 74~89%**. 실무는 후자입니다 |
| "요약을 계속 시키면 깔끔해진다" | **Brevity bias·Context collapse** — 반복 요약은 디테일을 잃고, 누적된 지식은 그럴듯하지만 쓸모없는 일반론으로 표류합니다 |
| "곁가지 질문 하나쯤은 괜찮다" | 그 문답이 대화에 영구히 남아 재전송되고, **방해자로 작동해 본 작업 정확도까지** 떨어뜨립니다. `/btw`로 격리 |
