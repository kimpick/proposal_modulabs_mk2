## 3. 루프 엔지니어링 개념 (보고서 인용)

- 정의: 에이전트가 행동(Act) → 관찰(Observe) → 추론(Reason) → 반복(Repeat) 사이클을 종료 논리(Termination Logic) 충족까지 자율 실행하는 아키텍처
- 배경: 2026년 6월 Claude Fable 5 출시, Boris Cherny (Claude Code 개발자) 선언 — "나는 더 이상 프롬프트를 지시하지 않는다. 루프를 작성한다"
- Vibe Coding과 구분: 직관이 아닌 **제약 조건·가드레일·엔지니어링 설계** 기반

### 핵심 기술적 난제

- **오토컴팩트(Auto-compact) 무한 루프 버그**: 컨텍스트 비대화 → 압축 실패 → 하위 에이전트 무한 재생성 → 자원 고갈·API 비용 폭증
- **컨텍스트 유실**: 압축 시 변수명 일반화, 스택 트레이스·아키텍처 결정 소실 → 퇴행 행동
- **사전 점유**: `/prime` 실행 시 가용 컨텍스트 약 22.5% (45,000 토큰) 미리 점유

### 방어 전략 (강사진 합의)

- Retry 횟수: 실무 5회 / **시연·실습 환경 3회** 제한
- 수동 `/compact` 적시 실행 교육
- 외부 메모리(md 파일) 기반 상태 관리 — 작업 계획, 구현 상태, 체크리스트, 다음 작업
