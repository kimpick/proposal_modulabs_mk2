멀티 에이전트 역할로 나눈다 :
내가 이 작업의 팀장이라면 누구에게 무엇을 맡길것인가?

목표 : 대시보드 첫 화면을 만들기

구조 : 리더 (사람) + 파이프라인형

1. 어떤 역할이 필요할까?
- 계획자 (Planner)
- 디자인 에이전트 (Builder/Designer)
- Frontend 개발 에이전트 (Builder)
- 검증 에이전트 (Validator)

2. i/o
계획자 : (Input) 어떤 대시보드를 만들고 싶은가에 대한 설명
           (Output) 대시보드 설계 기획안

디자인 : (Input) 대시보드 설계 계획안 + 디자인에 대한 설명
           (Output) 디자인 스키마 / 테마 파일? 스타일링

프론트엔드 : (Input) 대시보드 설계 기획안 + 디자인 파일
                 (Output) 프론트엔드 소스코드

검증 : (Input): 위에서 나온 모든 결과물 (기획안, 디자인, 소스코드)
        (Output) 소스코드의 결과물이 기획안을 만족하는가? +
디자인이 원래 의도한대로 되었는가? 에 대한 검증 결과

3. 사람이 개입하는 지점 (리더가 개입하는 지점)
- 대시보드 설계할 때 (대시보드 기획을 설명해야 함)
- 디자인 설계할 때 (디자인도 의도를 알려줘야 함)
- 검증 절차를 안내할 때 (나만의 검증 루틴 만들기)
- 검증 결과에 대한 검수

4. 로컬에서 어떻게 검증하지? (= QA를 어떻게 하지?)
- 브라우저 MCP : 브라우저에 접속해서 하나씩 눌러보거나/디자인 검증
- build/typecheck/lint 명령어 : 소스코드의 결과 품질을 관리하기
