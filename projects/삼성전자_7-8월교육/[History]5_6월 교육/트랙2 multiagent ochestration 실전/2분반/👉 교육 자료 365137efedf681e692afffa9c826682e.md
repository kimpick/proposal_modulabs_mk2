# 챕터 1 - 미니실습 정리

```jsx
멀티 에이전트 역할로 나눈다 :
내가 이 작업의 팀장이라면 누구에게 무엇을 맡길것인가?

목표 : 대시보드 첫 화면을 만들기

구조 : 리더 (사람) + 파이프라인형

1. 어떤 역할이 필요할까?
- 계획자 (Planner)
- 디자인 에이전트 (Builder/Designer)
- Frontend 개발 에이전트 (Builder)
- 검증 에이전트 (Validator)

2. i/o
계획자 : (Input) 어떤 대시보드를 만들고 싶은가에 대한 설명
           (Output) 대시보드 설계 기획안

디자인 : (Input) 대시보드 설계 계획안 + 디자인에 대한 설명
           (Output) 디자인 스키마 / 테마 파일? 스타일링

프론트엔드 : (Input) 대시보드 설계 기획안 + 디자인 파일
                 (Output) 프론트엔드 소스코드

검증 : (Input): 위에서 나온 모든 결과물 (기획안, 디자인, 소스코드)
        (Output) 소스코드의 결과물이 기획안을 만족하는가? +
디자인이 원래 의도한대로 되었는가? 에 대한 검증 결과

3. 사람이 개입하는 지점 (리더가 개입하는 지점)
- 대시보드 설계할 때 (대시보드 기획을 설명해야 함)
- 디자인 설계할 때 (디자인도 의도를 알려줘야 함)
- 검증 절차를 안내할 때 (나만의 검증 루틴 만들기)
- 검증 결과에 대한 검수

- 브라우저 MCP : 브라우저에 접속해서 하나씩 눌러보거나/디자인 검증
- build/typecheck/lint 명령어 : 소스코드의 결과 품질을 관리하기
```

# 챕터 3 : 역할 카드 템플릿

```markdown
# 기깔나는 디자이너

- 목적 : 주어진 입력을 만족하는 디자인 파일을 만든다.
- 입력 : 디자인에 대한 분위기, 설명, 색감 등...
- 출력 : design.md 파일
- 사용할 도구 : 없음
- 수정 가능 범위 : 수정 불가능
- 조심할 점 : AI가 만든거 같지 않은 디자인처럼
- 완료 기준 : design.md가 작성된다.

# 코드 리뷰어

- 목적 : 주어진 코드를 비판적인 시각에서 리뷰한다
- 입력 : 소스코드
- 출력 : 비판적인 시각으로 리뷰된 내용
- 사용할 도구 : 코드 읽는 도구
- 수정 가능 범위 : 수정 불가능 (리뷰해야함)
- 조심할 점 : 애매한 부분은 애매하다고 남겨두기
- 완료 기준 : 모든 코드를 다 훑어본 다음 완료 할것

# TDD 에이전트

- 목적 : 코드의 구현을 만족하는 테스트 코드 초안을 만든다
- 입력 : 테스트 코드로 만들 코드 또는 테스트 케이스 
- 출력 : 테스트 코드
- 사용할 도구 : 코드 읽는 도구, 코드 쓰는 도구
- 수정 가능 범위 : 테스팅 관련 코드만
- 조심할 점 : 테스트 외적인 부분을 다루지 않도록
- 완료 기준 : 테스트 코드가 작성된다

```

## 설계 프롬포트

```markdown
멀티 에이전트 오케스트레이션 관리 대시보드를 만들고 싶습니다.
내가 선택한 스택은 HTML + CSS + JS 입니다.

목표:
- 에이전트 카드 (에이전트 정보, 상태, ...)
- 작업 상태 목록 (작업 요약, 상태, 배정된 에이전트, ...)
- 로그 또는 메모 패널 (에이전트 실행 로그, 메모, ...)
- 모델 사용 전략 체크리스트 (위원회형, 리더형, ...)

10~20분 단위의 구현 계획을 제안해 주세요.
작은 모델도 수행할 수 있게 범위를 잘게 나눠 주세요.

보강하면 좋을 내용이 있다면 추천해주세요.
@planner 에이전트를 활용하세요.
대시보드 계획 파일을 프로젝트에 저장해주세요
```
