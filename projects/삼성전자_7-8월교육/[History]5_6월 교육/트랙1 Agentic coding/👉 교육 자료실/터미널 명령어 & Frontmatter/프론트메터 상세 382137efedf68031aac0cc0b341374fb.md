# 프론트메터 상세

## 1. Claude Code — Subagent frontmatter

경로 예시:

```
.claude/agents/code-reviewer.md
~/.claude/agents/code-reviewer.md
```

템플릿:

```markdown
---
name: code-reviewer
description: 코드 변경 후 품질, 보안, 테스트 누락, 회귀 위험을 리뷰해야 할 때 사용한다.
tools: Read, Glob, Grep, Bash
disallowedTools: Write, Edit
model: sonnet
permissionMode: default
maxTurns: 8
skills:
  - api-conventions
  - test-review
memory: project
effort: high
background: false
isolation: worktree
color: blue
---

너는 코드 리뷰 전담 subagent다.

항상 다음 순서로 판단한다.

1. 변경 파일과 영향 경로를 먼저 파악한다.
2. correctness, security, regression, missing tests를 우선순위로 본다.
3. 스타일 지적은 실제 버그 위험과 연결될 때만 말한다.
4. 각 지적은 파일 경로, 근거, 재현/검증 방법을 포함한다.
5. 수정 제안은 최소 패치 단위로 제시한다.
```

핵심 옵션:

```
name              필수. 고유 식별자. lowercase/hyphen 권장.
description       필수. Claude가 언제 이 subagent에 위임할지 판단하는 라우팅 설명.
tools             허용 도구. 생략하면 전체 도구 상속.
disallowedTools   금지 도구.
model             sonnet / opus / haiku / fable / inherit / full model id.
permissionMode    default / acceptEdits / auto / dontAsk / bypassPermissions / plan.
maxTurns          최대 agentic turn 수.
skills            subagent 시작 시 preload할 skill 목록. 전체 skill 내용이 주입됨.
mcpServers        이 subagent에서 쓸 MCP 서버.
hooks             subagent 범위 lifecycle hook.
memory            user / project / local persistent memory scope.
background        true면 항상 background task.
effort            low / medium / high / xhigh / max.
isolation         worktree 등 격리 실행.
color             UI 표시 색상.
```

## 2. Claude Code — Skill frontmatter

경로 예시:

```
.claude/skills/api-conventions/SKILL.md
~/.claude/skills/api-conventions/SKILL.md
```

템플릿:

```markdown
---
name: api-conventions
description: 이 저장소에서 API endpoint, request validation, error response, DTO/schema convention을 작성하거나 수정할 때 사용한다.
when_to_use: API route, controller, service endpoint, request/response schema, validation, error format을 만들거나 고칠 때.
argument-hint: "[target-file-or-feature]"
arguments:
  - target
disable-model-invocation: false
user-invocable: true
allowed-tools: Read Grep Glob
disallowed-tools: Bash(rm *) Bash(git push *)
model: inherit
effort: medium
---

이 skill은 API 구현 규칙을 제공한다.

규칙:

1. endpoint 이름은 RESTful하게 작성한다.
2. request validation을 누락하지 않는다.
3. error response format을 기존 코드베이스와 맞춘다.
4. DTO/schema 변경 시 관련 test와 caller 영향 범위를 확인한다.
5. 기존 convention이 있으면 새 규칙을 만들지 말고 기존 패턴을 따른다.

대상: $target
```

핵심 옵션:

```
name                       표시 이름. 생략 시 디렉터리명 기본값.
description                권장. Claude가 skill 사용 여부를 판단하는 핵심 설명.
when_to_use                trigger phrase, 예시 요청, 사용 조건. description에 붙어서 라우팅에 사용됨.
argument-hint              slash/autocomplete에서 보이는 인자 힌트.
arguments                  $name 형태로 본문에서 쓸 positional argument 이름.
disable-model-invocation   true면 Claude가 자동 호출 못 함. 수동 /skill 용도.
user-invocable             false면 / 메뉴에서 숨김.
allowed-tools              skill 활성 중 승인 없이 쓸 수 있는 도구.
disallowed-tools           skill 활성 중 제거할 도구.
model                      skill 활성 중 사용할 모델. inherit 가능.
effort                     skill 활성 중 reasoning effort.
context                    inline / fork 계열 실행 컨텍스트.
agent                      context: fork일 때 사용할 subagent.
```

## 3. Codex — Subagent custom agent 파일

Codex subagent는 `--- YAML frontmatter ---`가 아니라 **TOML 파일**

경로 예시:

```
.codex/agents/reviewer.toml
~/.codex/agents/reviewer.toml
```

템플릿:

```toml
name = "reviewer"
description = "PR과 코드 변경에서 correctness, security, regression, missing tests를 검토해야 할 때 사용한다."
model = "gpt-5.4"
model_reasoning_effort = "high"
sandbox_mode = "read-only"
nickname_candidates = ["Atlas", "Delta", "Echo"]

developer_instructions = """
너는 코드 리뷰 전담 subagent다.

항상 다음 원칙을 따른다.

1. 변경 파일과 실제 실행 경로를 먼저 파악한다.
2. correctness, security, regression, missing tests를 우선한다.
3. 스타일만의 지적은 피한다.
4. 모든 지적은 파일 경로, 근거, 영향, 검증 방법을 포함한다.
5. 코드 변경은 하지 말고 리뷰 결과만 반환한다.
"""

[skills.config]
# 필요한 경우 skill 관련 설정을 여기에 둔다.
```

핵심 옵션:

```
name                     필수. Codex가 spawn/ref할 agent 이름.
description              필수. 언제 이 agent를 쓸지에 대한 설명.
developer_instructions   필수. agent의 핵심 행동 지침.
nickname_candidates      선택. UI 표시용 별칭 후보.
model                    선택. 사용할 모델.
model_reasoning_effort   선택. reasoning effort.
sandbox_mode             선택. read-only / workspace-write 등.
mcp_servers              선택. agent 전용 MCP 설정.
skills.config            선택. agent별 skill 설정.
```

## 4. Codex — Skill frontmatter

경로 예시:

```
.agents/skills/code-review/SKILL.md
~/.agents/skills/code-review/SKILL.md
```

템플릿:

```markdown
---
name: code-review
description: 코드 변경, PR, diff, commit을 리뷰해서 correctness, security, regression, missing tests를 찾아야 할 때 사용한다.
---

이 skill은 Codex가 코드 리뷰를 수행할 때 따른다.

절차:

1. 변경 범위를 확인한다.
2. 관련 실행 경로와 호출자를 추적한다.
3. correctness, security, regression, missing tests를 우선 검토한다.
4. 공식 문서 확인이 필요한 API는 추측하지 말고 문서 확인을 요청하거나 MCP/docs 경로를 사용한다.
5. 결과는 severity, file, evidence, recommendation 순서로 정리한다.

출력 형식:

- Critical findings
- High-confidence risks
- Missing tests
- Verification commands
```

## 실전 기준 핵심만

Claude:

```
Claude subagent = .claude/agents/*.md
상단 YAML frontmatter + body가 subagent system prompt.

Claude skill = .claude/skills/*/SKILL.md
상단 YAML frontmatter + body가 reusable instruction.
```

Codex:

```
Codex subagent = .codex/agents/*.toml
YAML frontmatter 아님. TOML config file.

Codex skill = .agents/skills/*/SKILL.md
상단 YAML frontmatter + body가 reusable instruction.
```

가장 중요한 작성 원칙

```
description은 “무엇을 하는가”가 아니라
“언제 반드시 이걸 써야 하는가”로 써야 한다.
```

예를 들어 나쁜 description:

```yaml
description: 코드 리뷰를 한다.
```

좋은 description:

```yaml
description: 코드 변경, PR diff, commit 후 correctness/security/regression/missing-test 위험을 검토해야 할 때 사용한다.
```
