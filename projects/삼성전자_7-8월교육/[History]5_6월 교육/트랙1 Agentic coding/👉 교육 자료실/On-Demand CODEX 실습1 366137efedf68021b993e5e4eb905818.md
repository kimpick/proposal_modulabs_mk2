### 2-1. hooks 방법 1 : - OS shell script 기반 (PLAN 모드로 진행)

```markdown
목표: 현재 repo, OS/shell, git 상태를 먼저 파악한 뒤, Codex Stop command hook 1개를 생성하라.
이 Stop hook은 `index.html`이 생성/수정/변경된 경우에만 검증 후 auto commit한다.
이번 단계는 hook 생성과 정적 검증까지만 수행한다. 실제 E2E 실행은 사용자가 `/hooks`에서 trust 승인한 뒤 별도 진행한다.

반드시 먼저 공식 문서를 확인하라.

* https://developers.openai.com/codex/hooks
* https://developers.openai.com/codex/rules

사전 점검:

* OS/shell 확인
* `git rev-parse --show-toplevel`로 git root 확인
* 현재 branch/status 확인
* `git config user.name`, `git config user.email` 확인
* 기존 `.codex/hooks.json`, `.codex/hooks/**` 확인
* remote는 확인만 하고 절대 push하지 말 것

생성/수정 범위:

* `.codex/hooks.json`
* `.codex/hooks/hook.log`
* Windows/PowerShell이면 `.codex/hooks/stop-test-and-commit.ps1`
* WSL/Linux/macOS이면 `.codex/hooks/stop-test-and-commit.sh`

hook 요구사항:

* `.codex/hooks.json`만 사용한다.
* `.codex/config.toml` inline hook은 사용하지 않는다.
* event는 `Stop`만 사용한다.
* handler는 `command`만 사용한다.
* Stop에는 matcher를 사용하지 않는다.
* script 내부에서 `git rev-parse --show-toplevel`로 repo root를 계산한다.
* 모든 로그는 `.codex/hooks/hook.log`에 남긴다.
* stdout은 JSON만 출력한다.
* git/test 출력은 stdout에 흘리지 말고 hook.log에만 기록한다.

Stop hook 동작:

* 시작 로그: `[HOOK] Stop test and commit started`
* stdin JSON에서 `permission_mode`가 `plan`이면 commit하지 않고 `{ "continue": true }` 출력
* `git status --porcelain -- index.html` 결과가 없으면 commit하지 않고 `{ "continue": true }` 출력
* `index.html`이 삭제된 상태면 commit 금지 + JSON block reason 출력
* `index.html` 변경이 있으면 `<html`, `<head`, `<body` 포함 여부 검사
* 검사 실패 시 commit 금지 + JSON block reason 출력
* `git user.name` 또는 `git user.email`이 없으면 commit 금지 + BLOCKED reason 출력
* 검증 성공 시 `git add -- index.html` 후 `git commit -m "auto: update index.html"`
* commit 성공 시 commit hash를 hook.log에 기록
* `git push`는 절대 실행하지 않는다.
* 다른 변경 파일은 자동 commit하지 않는다.

금지:

* `.git/hooks` 수정
* 프로젝트 외부 수정
* 이번 단계에서 `index.html` 생성/수정
* remote/branch 변경

정적 검증:

* `.codex/hooks.json` JSON 유효성 검사
* Windows면 `.ps1` 문법 검사
* Linux/macOS/WSL이면 `.sh` 문법 검사
* `.codex/hooks/hook.log` 생성 확인
* 실제 hook 실행 성공은 단정하지 말 것
* `/hooks` trust 승인 이후 실행된다고 보고할 것

Plan 모드에서 먼저 짧게 보고하라:

1. 감지한 OS/shell
2. git root / branch / status
3. git user 설정 여부
4. 생성할 script 종류
5. 생성/수정 파일
6. 정적 검증 방법
7. E2E 미실행 사유

계획 승인 후 구현하라.

최종 보고:

* OS/shell
* git root와 branch
* 생성/수정 파일
* Stop hook 구성 요약
* 정적 검증 결과
* `/hooks` trust 필요 여부
* E2E 미실행 명시
* `index.html` 변경 시에만 auto commit하도록 구성했는지
* `git push` 미실행 확인
```

### os 기반 hooks 에러 발생 시 던져볼만한 프롬프트

```markdown
사용자는 로컬 repo/user 권한 기준으로 hook이 설계되는데, 
실제로는 Codex의 trust 계층, hook hash trust, cwd, sandbox 권한, Git safe.directory, 다중 hook 계층이 섞인 별도 실행 컨텍스트에서 돈다.
현재 발생 원인을 아래 기준으로 확장 사고하여 파악하고, 해결책 구현을 제시하라. 
1. cwd 불일치
   hook이 항상 repo root에서 도는 게 아니라 세션 cwd 영향을 받음.

2. trust 불일치
   project trust와 hook hash trust가 별개임.
   project가 untrusted면 repo/.codex hook 자체가 안 로드됨.

3. hook 계층 불일치
   user-level, project-level, plugin hook이 병합 실행됨.
   내가 만든 hook이 아니라 다른 hook이 code 1을 낼 수 있음.

4. sandbox 권한 불일치
   수동 PowerShell에서는 git commit 가능해도,
   Codex hook 프로세스에서는 .git 쓰기가 막힐 수 있음.

5. Git ownership 불일치
   hook 실행 계정/환경이 달라 Git이 dubious ownership으로 repo를 거부할 수 있음.

6. hook trust hash 불일치
   hook 파일을 조금만 바꿔도 hash가 바뀌고 다시 trust 필요.
```

```
현재 repo에 `index.html` 전용 auto commit Stop hook을 설계하라.

목표:

* Codex 작업 종료 시 `index.html`이 수정된 경우에만 자동 커밋한다.
* `index.html` 변경이 없으면 아무것도 커밋하지 않는다.
* 다른 파일은 절대 자동 커밋에 포함하지 않는다.
* 이번 턴에서는 테스트를 실행하지 않는다. 파일 생성/구현까지만 진행한다.

핵심 원칙:

* Python wrapper로 구현한다.
* 절대경로 하드코딩 금지.
* Windows는 `py`, macOS/Linux는 `python3` 사용.
* wrapper는 표준 라이브러리만 사용한다.
* `git add -A`, `git add .` 금지.
* 반드시 `git add -- index.html`만 사용한다.
* `.git` 쓰기는 permission profile이 아니라 Codex Rules로 해결한다.
* Stop hook에서 호출되는 Python wrapper 명령만 sandbox 밖 실행을 allow한다.
* `git commit`, `git add .`, `git add -A`, `py` 단독 실행은 allow하지 않는다.
* hook 실행 로그를 반드시 남긴다.

필요한 상위 디렉터리가 없으면 먼저 생성하라.

생성할 파일:

* `.codex/rules/default.rules`
* `.codex/hooks.json`
* `tools/hooks/auto_commit_index_html.py`
* `docs/hooks/auto_commit_index_html.md`
* `.codex/logs/auto_commit_index_html.log`는 wrapper 실행 시 자동 생성

Rules 요구사항:

* `.codex/rules/default.rules`에 Stop hook wrapper 명령만 sandbox 밖 실행 허용 규칙을 추가한다.
* Windows: `py tools/hooks/auto_commit_index_html.py`만 allow.
* macOS/Linux: `python3 tools/hooks/auto_commit_index_html.py`만 allow.
* `git commit`, `git add .`, `git add -A`, `py` 단독 실행은 allow하지 않는다.

Stop hook 요구사항:

* `.codex/hooks.json`에 Codex Stop 이벤트를 등록한다.
* Stop 이벤트에서 Python wrapper를 호출한다.
* Windows command: `py tools/hooks/auto_commit_index_html.py`
* macOS/Linux command: `python3 tools/hooks/auto_commit_index_html.py`

wrapper 동작:

1. repo root를 `git rev-parse --show-toplevel`로 찾는다.
2. `.codex/logs/auto_commit_index_html.log`를 append 모드로 준비한다.
3. 실행 시각, repo root, Python executable, OS 정보를 로그에 기록한다.
4. Python 실행 가능 여부, Git 실행 가능 여부, Git repo 여부, `index.html` 존재 여부, `git user.name`, `git user.email`, `.git/index.lock` 존재 여부를 확인한다.
5. `git status --porcelain -- index.html`로 `index.html` 변경 여부만 확인한다.
6. 변경이 없으면 `NO_INDEX_HTML_CHANGE` 출력 및 로그 기록 후 종료한다.
7. 변경이 있으면 `INDEX_HTML_CHANGED`를 로그에 기록한다.
8. `git add -- index.html`만 실행한다.
9. pre-commit이 설치되어 있으면 `sys.executable -m pre_commit run --files index.html`을 실행한다.
10. pre-commit이 없으면 `PRE_COMMIT_NOT_INSTALLED_SKIP`을 출력 및 로그 기록하고 계속 진행한다.
11. pre-commit 실패 시 commit하지 않고 `PRE_COMMIT_FAILED`를 출력 및 로그 기록한다.
12. pre-commit 이후 다시 `git add -- index.html`만 실행한다.
13. `git diff --cached --quiet -- index.html`로 staged 변경 여부를 확인한다.
14. staged 변경이 없으면 `NO_STAGED_INDEX_HTML_CHANGE` 출력 및 로그 기록 후 종료한다.
15. staged 변경이 있으면 `git commit -m "auto: update index.html"`을 실행한다.
16. 성공 시 `COMMIT_SUCCESS`와 commit hash를 출력 및 로그 기록한다.
17. 실패 시 `GIT_COMMIT_FAILED`와 에러 메시지를 출력 및 로그 기록한다.

로그 요구사항:

* 로그 경로는 `.codex/logs/auto_commit_index_html.log`.
* 로그 디렉터리가 없으면 생성한다.
* 모든 종료 경로를 로그에 남긴다.
* 기록 상태 예시:

  * `START`
  * `ENV_CHECK_OK`
  * `NO_INDEX_HTML_CHANGE`
  * `INDEX_HTML_CHANGED`
  * `PRE_COMMIT_NOT_INSTALLED_SKIP`
  * `PRE_COMMIT_FAILED`
  * `NO_STAGED_INDEX_HTML_CHANGE`
  * `COMMIT_SUCCESS`
  * `GIT_COMMIT_FAILED`
* 로그 파일은 자동 커밋 대상에 포함하지 않는다.
* 자동 커밋 대상은 오직 `index.html`이다.

문서 요구사항:

* `docs/hooks/auto_commit_index_html.md`에 목적, 파일 구조, Rules 역할, Stop hook 역할, wrapper 동작, 로그 위치, trust 필요 여부를 간단히 작성한다.
* 사용자가 `/hooks` 또는 rules trust를 해야 실제 Stop hook이 실행될 수 있음을 명시한다.
* 테스트 방법은 문서에만 적고, 이번 턴에서는 실제 테스트를 실행하지 않는다.

이번 턴 금지사항:

* 테스트 실행 금지.
* 임시 복제본 생성 금지.
* `index.html` 임의 수정 금지.
* `git add -A` 사용 금지.
* `git add .` 사용 금지.
* hook/rules/docs/log 파일을 자동 커밋하지 말 것.

최종 보고:

* 생성/수정 파일 목록
* Rules allow 설정 내용
* Stop hook 동작 방식
* wrapper 동작 요약
* 로그 파일 경로
* 사용자가 `/hooks` 또는 rules trust를 해야 하는지 여부
* 테스트는 실행하지 않았다고 명시
```
