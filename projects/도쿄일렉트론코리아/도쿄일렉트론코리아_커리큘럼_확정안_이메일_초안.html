지난 회의에서 전달 주신 커리큘럼 수정 요청을 강사님(김민수)과 함께 검토하였습니다. 전문가 소견과 교육 운영 측면을 종합하여 최종 커리큘럼 구성안을 제안 드리오니 검토 부탁드립니다.

1. 주요 조정 사항

  1. 총 시간 조정 (29H → 24H)
    전달 주신 초안이 총 29시간으로 협의된 24시간(3일×8H) 대비 5시간 초과되어, 중복 항목 통합과 우선순위 조정을 진행했습니다.
  2. RAG 기초 강화 (1일차 추가)
    사전 기초 교육에 LangChain 기본 구조가 포함되지 않은 점이 확인되어, RAG 구축에 필요한 기초 개념과 LangChain 기본 사용법(PromptTemplate, ChatPromptTemplate, LCEL Q&A 챗봇 실습)을 1일차에 추가했습니다.
  3. 고급 프롬프트 엔지니어링 압축
    일반 프롬프트 작성법 전반을 다루는 대신, RAG 검색 품질 개선에 직접 연결되는 Query Rewriting · Multi-Query · HyDE · Semantic Routing 중심으로 재정의했습니다. Chain-of-Thought는 최신 모델·RAG 파이프라인에서 효과가 일관되지 않아 의도적으로 제외했습니다.
  4. Langfuse 평가/Tracing 추가 (3일차)
    3일차 평가 모듈에 Langfuse 기반 RAG 요청 Trace 확인과 RAGAS · TruLens와의 역할 구분을 추가했습니다.
  5. 하이브리드 검색 통합 (2일차)
    당초 2일차의 하이브리드 검색과 3일차의 BM25 Sparse + Dense 결합은 동일한 구현 방식이므로 2일차의 Hybrid Retrieval 파트로 통합했습니다.
  6. 벡터화 강화 방향 — 임베딩·청킹 중심
    본격적인 Graph RAG / Graph-enhanced RAG는 짧은 시간 내 깊이 있게 다루기 어려워 심화 과정으로 이관합니다. 대신 이번 과정에서는 벡터화의 핵심 요소인 도메인에 맞는 임베딩 모델 선택, 적절한 차원 수, 문서 구조에 따른 청킹 전략(고정 길이/재귀적/구조 기반/시맨틱) 을 1·2일차에 걸쳐 강화합니다.
  7. 벡터 DB 튜닝 → 운영 환경별 DB 선택
    벡터 DB 내부 저장 방식·옵션 튜닝은 수학적 이해 부담이 커 이번 교육 범위에 적절치 않다고 판단했습니다. 대신 컴퓨팅 자원과 운영 환경에 따른 벡터 DB 선택 관점 (예: GPU 가속을 위한 Faiss, 분산 컴퓨팅을 위한 Qdrant)으로 다루겠습니다.
  8. Agentic RAG — 추가 학습 자료로 대체
    Agentic RAG는 LangGraph 학습이 선행되어야 하므로 이번 과정에서는 본격적으로 다루지 않고, 추가 학습 자료 공유로 대체합니다. 전체 교육 밀도가 높은 만큼, 시간 여유와 수강생 참여도를 보고 기본 원리 수준에서 소개 여부를 유연하게 결정하겠습니다. 본격적인 내용은 후속 심화 과정에서 다루는 것을 제안 드립니다.

2. 실습 자료 (제안)

도메인 유사 외부 문서 공유가 어려우신 점 확인했습니다. 이에 외부 문서(예: 미래에셋 ETF 자료) 대신, 강사님께서 준비하신 약 190페이지 분량의 문서를 실습 베이스로 활용하는 방향을 제안 드립니다.

회의 시 말씀드린 미니 경진대회(최종 과제)도 동일한 강사 제공 자료를 기반으로 진행되므로, 수강생분들께서 별도의 내부 문서를 준비하지 않으셔도 됩니다. 다만 사내 데이터로 직접 적용해 보시기를 원하시는 분은 개별적으로 준비하셔서 실습 시간에 활용하실 수 있습니다.

3. 최종 커리큘럼 (3일 × 8H = 24H)

일자 주제 및 세부 내용
1일차 (8H)
RAG 기초 및 데이터 처리
  • LangChain 기본 구조와 간단한 Chain 실습
  • PromptTemplate, ChatPromptTemplate, Few-shot 기본 사용법
  • LCEL 기반 Q&A 챗봇 실습
  • RAG 개념 이해: LLM 단독 사용의 한계, Retrieval + Generation 구조
  • 임베딩과 벡터 검색 원리
  • ChromaDB 기반 벡터 저장소 구축 및 검색 실습
  • ChromaDB 기본 인덱싱 방식인 HNSW 포함 벡터 인덱싱 개념
  • 기본형 RAG 파이프라인 구성 실습
  • Naive RAG의 한계 진단
  • 고정 길이 청킹, 재귀적 청킹, 구조 기반 청킹, 시맨틱 청킹 비교
  • Query Rewriting을 통한 검색 질문 개선 실습
2일차 (8H)
검색 고도화 및 Advanced RAG 기법
  • Multi-Query Retrieval: 하나의 질문을 여러 검색 쿼리로 확장
  • HyDE: 가상 답변을 생성해 검색 품질 보완
  • Semantic Routing: 질문 유형에 따라 검색 경로 선택
  • Hybrid Retrieval: BM25 Sparse Retrieval + Dense Retrieval 결합
  • RRF: Sparse / Dense 검색 결과를 순위 기반으로 결합
  • Cross-Encoder Re-ranking: 검색 후보 재정렬
  • Context Filtering & Compression: 중복·잡음 제거 및 질문 기준 문맥 압축
  • Multi-Representation Indexing: 원문 외 요약/대표 표현을 함께 활용하는 인덱싱 패턴
3일차 (8H)
평가, 운영 모니터링, 지식그래프 기초
  • 평가셋 설계: 질문, 기준 답변, 근거 문서 구성
  • Retrieval 평가: Hit@K, Recall@K 계산
  • Generation 평가: Faithfulness 중심의 LLM-as-a-Judge 평가
  • 수동 평가 지표와 RAGAS 지표의 관계
  • RAGAS 입력 구조: user_input, retrieved_contexts, response, reference
  • Langfuse 기반 RAG 요청 Trace 확인
  • RAGAS, Langfuse, TruLens의 역할 구분
  • 관계형 질문에서 Vector RAG가 흔들리는 지점 확인
  • 온톨로지 / 지식그래프 기초: Entity, Relation, Triple 개념
  • 짧은 문장에서 트리플 추출 미니 실습
  • Graph RAG로 확장하기 전 설계 체크리스트
  • 미니 경진대회 (최종 과제)
