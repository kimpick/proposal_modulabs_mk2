## 영역별 상세 의견

### 1. 선행학습과의 매칭 — 기존 교안 유지 + 추가 위주

- **강사 의견**: 도쿄일렉트론 구성원분들의 선행학습과 강사 보유 수업자료가 **겹치지 않음**. 그분들이 RAG 기본 원리를 선행학습하지 않은 상태이기 때문.
- **변경 방향**: 회의에서 공유드린 교안의 대부분 내용을 **살리고**, **내용 추가 위주**로 변경.

- **변경 방향**: **2일차 하이브리드 검색 파트에서 함께** 다룸 (자연스러운 흐름).

### 5. 고급 프롬프트 엔지니어링 — RAG 검색 개선 중심으로 재정의

- **강사 의견**:
  - 일반적인 프롬프트 작성법 전체를 다루기보다 **RAG 검색 품질 개선과 직접 연결되는 내용 중심**으로 축소 검토 필요.
  - **Chain-of-Thought 한계**: 초기 LLM 활용에선 효과적이었으나 최신 모델에선 항상 품질 향상으로 이어지지 않을 수 있음. RAG 파이프라인에선 **답변이 길어지거나 검색 근거보다 추론 문장이 강조**될 수 있음.
  - 일반 프롬프트 기법보다 **검색 질문 개선·검색 후보 확장** 방식이 더 적절.
- **변경 방향**: **Query Rewriting / Multi-Query / HyDE / Semantic Routing** 중심.
- **모두연 응답**: 좋습니다. 자세한 피드백 감사합니다. (합의)

- **변경 방향**: **3일차로 이동** (당초 2일차 맨 뒤에 배치 검토했으나 3일차 콘텐츠와 더 잘 어울림).

### 10. 하이브리드 검색 의미 재정의 → Graph RAG 범위 한정

- **강사 의견**:
  - 처음엔 2일차의 하이브리드 검색을 **BM25/Sparse Retrieval + Embedding 기반 Dense Retrieval 결합**으로 이해. 일반적 RAG 커리큘럼에서 "하이브리드 검색"은 보통 이 의미로 쓰임.
  - 그런데 고객사가 의도한 하이브리드 전략이 **3일차의 온톨로지 + LLM 기반 벡터화**까지 포함하는 것이라면, BM25+Dense 결합보다는 **Graph RAG / Graph-enhanced RAG** 쪽에 더 가까움.
  - **범위 우려**: Graph RAG를 본격적으로 다루려면 Entity/Relation 추출, 온톨로지 구조화, 그래프 기반 검색, 기존 벡터 검색과의 결합까지 들어가야 해서 **범위가 꽤 커질 수 있음**. 자료 만들면서 해당 범위까지 다뤄도 문제없을지 파악 예정.
- **변경 방향**: 본격 Graph RAG는 **심화 교육 과정에서 중점적으로** 다루므로, 이번 교육과정에는 **녹일 수 있는 수준**으로만 한정.
- **모두연 응답**: 본격적인 Graph RAG는 심화 과정 영역으로 분리, 이번 과정엔 녹일 수 있는 수준만 요청. (합의)
