**요청**: 위 3대 엔지니어링(하네스·루프·그래프)을 **"AI 팩토리 구축"**이라는 과정 제목으로 종합한 1일 8시간 교육. (v4 확정 — 참고 문서는 §7.6)

### 5단 스택 (9월 리서치 문서 기준)

```
Prompt Engineering    — 요청 한 번을 어떻게 쓸 것인가
  └ Context Engineering  — 프롬프트 주변에 무엇을 넣을 것인가
     └ Harness Engineering — 도구·가드레일·검증이 돌아가는 시스템   ← 4월 교육
        └ Loop Engineering   — 에이전트 1개의 반복 자동화           ← 7-8월 교육
           └ Graph Engineering — 여러 에이전트·단계를 그래프로 연결  ← 9월 교육
```

- **핵심 명제**: 각 층은 아래 층을 대체하지 않고 **위에 쌓인다**. 에이전트 엔지니어링은 3개 층을 개발 워크플로우(이슈→설계→구현→리뷰→테스트→배포) 전체에 걸쳐 **조립**하는 것.
- **판단 기준 재사용**: "경로를 미리 그릴 수 있으면 그래프(Graph), 실행하면서 찾아야 하면 루프(Loop), 그것이 돌아갈 환경이 하네스(Harness)"

## 3. 과정 설계 방향

### 3.1 포지셔닝 (v4 — AI 팩토리 프레임)

- **과정명: "AI 팩토리 구축"** — 하네스 엔지니어링부터 그래프 엔지니어링까지를 하나의 서사로 묶는 상위 프레임. 참고 문서(§7.7)의 "루프→하네스→팩토리" 스택과 "라이트/다크 팩토리" 은유가 커리큘럼의 내러티브 척추
- **통합 입문 실전 과정** — 시리즈 수강 전제 없음. 3대 레이어를 처음부터 가르치되, "각 레이어별 독립 과정"이 아니라 **하루 안에 동작하는 AI 팩토리 1식을 조립**하는 관점
- **무API 설계가 차별점**: 구독 계정만으로 팩토리를 짠다 — 사내 실무 환경과 동일 조건에서 실습하므로 교육 직후 재현성 100%
- 만족도 전략: ① M1 워크숍 지도가 M5 청사진으로 회수 ② 의도적 실패→트레이스 진단→수습 3연타 ③ 라이트 스위치 판정·아우터 루프 등 "사람의 자리"라는 메시지성 강한 콘텐츠 (§7.7)

### 3.4 무API 아키텍처 — 설계 원리 (v3 신설)

```
[LangGraph 제어 평면]                    ← API 키 불필요 (순수 Python 오케스트레이션)
  StateGraph · conditional edge (코드)
  Checkpointer (중단·재개) · interrupt() (HITL 승인)
        │
        ├── 워커 노드: subprocess → claude -p "..." --output-format json
        │              ← 구독 OAuth 인증 (엔터프라이즈 플랜 포함)
        ├── 워커 노드: subprocess → codex exec --json "..."
        │              ← ChatGPT 구독 저장 인증
        └── 평가 노드: 린트·테스트·코드 평가자 (결정론적)
        │
[Langfuse 관측 계층]                      ← LLM API 불필요
  트레이스 수집 · Agent Graph View · 데이터셋 · 코드 평가자 스코어
```

- **핵심 원리**: 그래프 엔지니어링 철학("엣지는 코드, 라우팅은 작성 시점 결정")과 무API 제약이 정확히 일치 — 모델이 라우팅하면 API가 필요하지만, 엣지를 코드로 그리면 LangGraph는 LLM을 호출할 일이 없음
- **LLM 지능이 필요한 지점만** 구독 인증 CLI 워커로 위임. CLI가 인증·과금을 구독에 포함된 사용량으로 처리
- **주의사항 (강사 리허설 필수)**: ① `ANTHROPIC_API_KEY` env가 남아 있으면 구독 대신 API 과금 경로로 전환됨 → 실습 전 env 정리 가이드 ② Enterprise 관리자가 구독 로그인 차단 시 `oauth_org_not_allowed` 에러 → 사전 확인 ③ Claude Code `--print` 무세션 스케줄 실행은 버전에 따라 401 이슈 이력 → 교육 중 대화형 로그인 세션 유지 후 실행

### 7.6 AI 팩토리 프레임 — 참고 문서 분석 (v4)

고객 제공 문서 `하네스에서 AI 팩토리 까지.docx` = Addy Osmani **"Software Factories, Light and Dark"** (2026-07-21, Substack). 과정명·내러티브의 원천. 핵심 개념과 커리큘럼 반영 위치:

| 문서 핵심 개념 | 내용 | 반영 |
|---|---|---|
| **루프→하네스→팩토리 스택** | 루프=원자(한 에이전트가 한 일을 반복, 최소 단위) / 하네스=벽(샌드박스·도구·메모리·'완료' 게이트) / 팩토리=하네스된 루프들의 조직("더 큰 에이전트가 아니라 루프로 짠 조직도") | M1 3단 스택 + 모듈 순서(루프→하네스→그래프→팩토리) |
| **팩토리의 닫힌 루프** | 작업 큐 → 하네스 빌드 → 자동 검증 → 리뷰 게이트 → 배포 → 모니터링 → 다시 신호로 | M1 지형도, M5 청사진 구조 |
| **다크 팩토리·이해 부채** | 무인 검증(아무도 안 읽은 코드 출하)은 테스트가 초록인 채 comprehension debt를 쌓음 — Dex Horthy 4개월 무인 팩토리 실패 사례 | M1 라이트/다크, M5 의도적 실패 |
| **Back pressure** | "검증할 수 있는 만큼만 자율을 준다" — 병목은 생성이 아니라 검증. 검증 목이 안 넓어지면 생성을 빨리할수록 쌓일 뿐 | M1 원칙 소개, M4 그래프="back pressure를 다이어그램으로 그린 것" |
| **라이트 스위치 판정** | 싸고·자주·속일 수 없는 검증(그린-레드 오라클, 타입 게이트, 속성 테스트, 루브릭 리뷰 에이전트)만 무인화 자격. 전부 끄면 4개월 뒤 해체, 전부 켜면 리뷰 병목 — "스위치를 어디 둘지가 기술" | M5 라이트 스위치 판정 실습 |
| **3~10 스텝 rule** | 에이전트는 3~10스텝은 버티지만 20스텝 넘으면 컨텍스트 누적으로 실종 — 짧은 루프일수록 검증이 쉽다 | M2 종료 로직·가드레일 |
| **루프 vs 그래프** | 버그 수정을 순수 루프(즉흥 결정)와 그래프(재현→원인→수정→테스트, 실패는 수정으로 회귀·통과는 리뷰로)로 대비. "에이전트의 자유는 노드 안으로" / "대부분 결정론적 코드에 LLM 스텝을 적절히 뿌린 것"(Dex) | M4 도입부 사례 |
| **inner/outer 루프** | 에이전트=inner loop(조사·진단·수정·테스트·보고), 사람=outer loop(접근 결정·검증·승인·책임). 경계는 증거(diff·테스트·로그). "생산라인에서 일하는 게 아니라 라인 끝에서 설계하고 게이트를 지키는 것" | M5 아우터 루프 |
| **아키텍처=안전망** | 타입·테스트 심·짧은 콜스택·컴포넌트 경계·DI 등 평범한 아키텍처 습관이 에이전트 시대의 싸고 위조 불가능한 안전망으로 재취업 | M3 가이드·센서 |

### 8.2 핵심 개념 정의

- **세컨 브레인**: 자기 컴퓨터에 구축하는 개인 지식·실행 기반. 에이전트의 컨텍스트 원천이자 작업 실행 주체
- **LLM Wiki** (Karpathy 패턴, 2026-04): LLM이 유지보수하는 개인 위키 — 마크다운 파일이 세션을 넘어 복리로 쌓이는 지식베이스. **제품이 아닌 패턴** (도구 목록 표기 주의 — 트랙 1·형제 프로젝트 검토 교훈). raw 자료를 wiki로 컴파일하는 관점("Obsidian is the IDE; the LLM is the programmer; the wiki is the codebase")
- **Google OKF** (Open Knowledge Format): 2026-06 Google Cloud 공개 벤더 중립 마크다운 스펙. **v0.1 공개 → v0.2 현행(2026-07, 신뢰 신호 추가: sources·generated·verified·status·stale_after)**. 디렉터리 단위 번들 + YAML frontmatter `type` 필수 + 파일 간 상호 링크가 지식그래프 형성
- **Cowork류 로컬화**: 기존 Claude/ChatGPT 세션을 로컬 파일로 이관하는 작업. Anthropic Cowork는 로컬 폴더 기반 프로젝트 워크스페이스(챗 세션 네이티브 동기화는 없음 → 데이터 내보내기/커뮤니티 도구 활용). content.json 본문에서는 제품명 없이 "기존 Claude/ChatGPT 세션 로컬 이관"으로 일반화 서술
- **서사** (형제 프로젝트 `삼성전자MX_비개발자대상 하네스엔지니어링` 원용): "문서를 먼저 고치고, 그 문서로 에이전트를 만든다" — 지식 재편 → 지식그래프 → 에이전트 기반 → 자율 실행
- **hermes/OpenClaw**: OpenClaw 계열 자율 에이전트 런타임(오픈소스·비영리 재단, 구 Clawdbot/Moltbot). 자기 PC에서 구동, Telegram/WhatsApp/Discord/Slack 게이트웨이 연동 — 본 트랙 통합 실습의 "오픈소스 프로덕션 등가물"로 확장 과제에서 소개

### 8.5 무API 아키텍처

```
[지시 입력 — 로컬 CLI / 텔레그램(선택·Bot API getUpdates 롱폴링)]
        │ 메신저 명령(선택 경로는 로컬 게이트웨이 경유)
        ↓
[claude -p 헤드리스 워커 (구독 OAuth)]
        │  지식그래프 검색 → 자료 생성 → 출처 명기
        │  (종료 조건·재시도 상한·질문 회귀 가드레일)
[세컨 브레인]  ←——읽기——
  OKF 문서 번들
  + 지식그래프(링크·메타데이터)
  + AGENTS.md 탐색·인용 룰
        ↓
[SMTP 메일 자동화] --산출물 발송--> 업무용 메일
```

- LLM 지능은 구독 인증 CLI 워커만 사용(API 키 전무) — 트랙 1 §3.4 원칙 동일 적용
- 텔레그램 봇 토큰·SMTP 자격증명은 LLM API가 아니므로 무API 원칙 유지
- 트랙 1 주의사항(env 정리·oauth_org_not_allowed·무세션 401)이 그대로 적용됨 — 강사 리허설 필수
