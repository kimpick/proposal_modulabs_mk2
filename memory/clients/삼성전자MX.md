  → Tier별 실제 크레딧 수치와 환산 비율표는 **미확보** (오정아 프로 확인 대기)

## 5. 통한 것 / 통하지 않은 것

**통한 것**
- **하네스 엔지니어링(Harness Engineering)** 프레임워크 — Context / Constraints / Entropy 3축. 용어집까지 별도 문서화하며 이 고객사 전용 언어로 정착 [출처: 삼성전자MX_3_Harness/context.md, harness_terminology.md]
- 단순 툴 사용법이 아닌 **업무 적용 아이디어 기획까지** 포함하는 설계 [출처: 동일]
- **A/B 2안 병렬 제출** (9일 정규 / 5일 집중) — 기간 선택권을 주는 방식 [출처: 삼성전자MX_구미_9월/]
- 시니어 대상: 1일 5시간(트렌드 0.5H + 실습 4.5H), 툴 7개 집중, end-to-end 산출물 4종 [출처: CLAUDE.md 시니어 프리셋 — 근거가 이 고객사 260417 제안]
- **"문서를 먼저 고치고, 그 문서로 에이전트를 만든다"** 서사 — LLM Wiki(Karpathy 패턴) + Google OKF로 업무 문서 재편 → 지식그래프 → 하네스 → 업무 자동화. 모두연이 미팅에서 제시해 고객 긍정 [출처: 비개발자 건 요구조건.md §4, MEMORY.md §3]
- **루브릭을 배정 도구로 사용** — 고객이 "현재 수준 파악이 안 된다"고 했으므로 파일럿을 *수준 실측* 목적으로 재정의하고, 5축×4레벨 루브릭 결과로 기초/심화 배정 + 차수 편성. **개인 등급이 아니라 차수 설계용 집계 데이터**라고 명시해 사내 민감도를 피함 [출처: 비개발자 건 MEMORY.md §3]
- **여러 과정을 종합 제안서 1본에 다트랙으로 통합** — 고객이 "로드맵이 보이도록" 요구 [출처: 동일]
- 경영진 기조가 최상위 제약: 식상한 교육 배제 / 최신 트렌드 / "하네스 엔지니어링"·"멀티에이전트 연동" 키워드 직접 지목 / **"Wow" 요구** / 참석자 수준 편차 큼 [출처: 비개발자 건 요구조건.md §2]

**통하지 않은 것 / 조정된 것**
- 초기 3일 과정 → **2일로 축소** 요구 (기간 부담) [출처: 삼성전자MX_1/context.md]
- 클라우드 서버리스 **배포** 파트는 관심 낮음 → 대신 **MLOps 실무**(모델 정밀 평가, Langfuse 트래킹, 사내 인프라 적용 방어 논리)에 뎁스 요구 [출처: 동일]
- LLM/Token 등 기본 개념 이해도가 고르지 않아 보강 필요 [출처: 동일]
